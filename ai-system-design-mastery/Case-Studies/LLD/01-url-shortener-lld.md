# LLD Case Study 01 — URL Shortener, One Level Down

> **Grounding note.** The reference repositories contain **no OOP/LLD material**, and the source transcripts do not cover a URL shortener at the class level. This file is written from first principles and is not transcript-grounded. The answer shape follows the house template at [LLD/01 What is LLD and How to Answer](../../LLD/01-what-is-lld-and-how-to-answer.md). The **system** view — capacity numbers, the cache's 60× read amplification, storage choice, the analytics pipeline at scale — is owned by [URL Shortener (HLD)](../HLD/01-url-shortener.md) and is **not repeated here**. This file opens the boxes that HLD named and shows the classes inside them: what `ShortCodeGenerator` actually is, where the collision retry lives, what "idempotency" means as a data structure, and why `301` is a bug when you want analytics.

> **TL;DR** — The HLD said "hash or counter, cache-aside, 301 vs 302, async analytics". One level down that becomes six collaborators: a `Base62Encoder` that is a pure function of an integer, a `ShortCodeGenerator` strategy whose **collision policy is the interesting part** (a counter has none; randomness needs a bounded retry; a hash needs a salt bump), a `UrlRepository` with an **idempotency index** so the same long URL returns the same code, a `CacheAsideStore` whose real job is **single-flight** rather than lookup, a `RedirectResolver` that owns the 301/302 decision as data rather than as a constant, and a `ClickEventPublisher` with a **bounded queue that drops rather than blocks** because analytics must never delay a redirect. The three genuinely hard parts are the retry loop's bound, the single-flight, and the drop policy — and all three are about what happens under load, not about encoding.

> **60-second interview answer:** "Six classes. `Base62Encoder` is pure: integer in, string out, and the alphabet is a constructor argument so I can exclude look-alike characters. `ShortCodeGenerator` is a strategy with three implementations and a **bounded** collision retry — a counter cannot collide at all, which is why it is the default, and the random generator is the one that needs the loop. `UrlRepository` holds two indexes: code to URL, and a **hash of the long URL to code** for idempotency, because the same long URL submitted twice must return the same short code. `CacheAsideStore` wraps it with read-through and a **single-flight** so a cache miss on a hot code does not send a thousand requests to the database. `RedirectResolver` decides 301 versus 302 from a configurable policy, and I would default to 302 because 301 is cached by the browser and then your click analytics never see the click. `ClickEventPublisher` puts events on a **bounded** queue and drops when it is full, because a redirect must never wait on analytics."

## 1. Requirement clarification

### The questions to ask

| # | Question | What it decides | Default if they won't say |
|---|---|---|---|
| 1 | **Short code: generated or user-supplied?** | Whether there is a custom-alias path with its own validation | Generated by default, custom alias as an option |
| 2 | **Code length and alphabet?** | The encoder and the collision probability | 7 characters, base62 minus `0/O/1/l/I` |
| 3 | **Is the same long URL submitted twice?** | Whether there is an idempotency index at all | Yes — the same URL returns the same code |
| 4 | **Collisions: retry or avoid?** | The generator's shape | A counter avoids them; randomness retries, bounded |
| 5 | **301 or 302?** | Whether clicks are observable and whether a link can be re-pointed | 302, decided by a policy object |
| 6 | **Do clicks matter?** | Whether the publisher exists and whether it is allowed to block | Yes, and it may never block a redirect |
| 7 | **Cache invalidation?** | Whether there is a delete path | TTL plus explicit evict on delete |
| 8 | **Custom aliases and reserved words?** | A validation step before the generator | A denylist plus a format check |
| 9 | **Expiry?** | Whether a code can lapse and what a lapsed code returns | Optional TTL per link; `410 Gone` when lapsed |
| 10 | **One process or many?** | Whether the counter is local or distributed | One process for the model; the distributed range-allocator shown in §6 |

### The defaults to assume, stated plainly

> "I'll assume base62 with look-alikes removed, a 7-character code, server-generated with an optional custom alias, **idempotent creation** keyed on the long URL, a **counter-backed generator by default** because it cannot collide, **302** with the redirect status as a policy, and an **async, bounded, lossy-on-overflow** click publisher. Does that match, or do you want the redirect path first and the rest as follow-ups?"

### Non-goals

- No capacity estimation, no sharding, no multi-region — [the HLD owns that](../HLD/01-url-shortener.md) §2 and §5.
- No HTTP, no framework, no database driver. The repository is an interface with an in-memory implementation.
- No analytics aggregation — only the event and its publication.

### The four constraints that shape the design

1. **A redirect is on the critical path; a click event is not.** Their reliability requirements differ by orders of magnitude, so they must not share a code path.
2. **Creation is a write with an idempotency requirement.** The same long URL twice must not produce two codes, and "check then insert" is a race.
3. **A collision is a correctness event, and a retry loop without a bound is an outage.** The generator must fail loudly rather than spin.
4. **301 is irreversible in practice.** A browser that has cached a 301 will not ask again, which breaks both analytics and the ability to re-point a link.

**The split to say out loud:** *"The generator produces a candidate; it does not check whether the candidate is taken. That belongs to the service, because checking requires the repository and a retry policy, and a generator that could check would need the repository injected into every strategy."*

## 4. Interfaces / abstract classes / enums

```python
class ShortCodeGenerator(ABC):
    @abstractmethod
    def generate(self, url: str, attempt: int) -> str:
        """Return a CANDIDATE. `attempt` is the retry number, and every
        implementation must use it — a generator that ignores `attempt` returns
        the same colliding code on every retry and the loop spins until the
        bound. That is the single most common bug in this problem."""


class UrlRepository(ABC):
    @abstractmethod
    def insert(self, record: UrlRecord) -> None:
        """RAISES CodeTaken if the code exists. The check and the insert must be
        one operation — a `exists()` followed by an `insert()` is a race in
        which two requests both find the code free."""

    @abstractmethod
    def find_by_code(self, code: str) -> Optional[UrlRecord]: ...
    @abstractmethod
    def find_by_url_hash(self, url_hash: str) -> Optional[UrlRecord]: ...
    @abstractmethod
    def delete(self, code: str) -> bool: ...


class CacheStore(ABC):
    @abstractmethod
    def get(self, key: str) -> Optional[str]: ...
    @abstractmethod
    def set(self, key: str, value: str, ttl_seconds: int = 3600) -> None: ...
    @abstractmethod
    def delete(self, key: str) -> None: ...


class RedirectPolicy(ABC):
    @abstractmethod
    def status(self, record: UrlRecord) -> int: ...


class ClickEventPublisher(ABC):
    @abstractmethod
    def publish(self, event: ClickEvent) -> bool:
        """Returns False when the event was DROPPED. It must not raise and must
        not block — a redirect cannot fail because analytics is behind."""
```

**Four contract notes worth saying out loud:**

- **`insert` raises rather than returning a bool.** A collision must be impossible to ignore; a boolean return is a return value somebody will not check.
- **`generate` takes `attempt`.** This is the contract that makes the retry loop terminate.
- **`publish` returns a bool rather than raising.** Dropping is an expected outcome under load, not an error.
- **`CacheStore` is a port**, so the in-memory and Redis implementations are both first-class and the single-flight logic is testable without a network.

## 5. Complete working code (Python 3.10+)

> **Language note.** In Java: `Optional<UrlRecord>`, a `ConcurrentHashMap` with `putIfAbsent` for the atomic insert, and a `@FunctionalInterface` for the generator. In Go: `(UrlRecord, bool, error)` returns and a `sync.Mutex`. The **bounded retry, the idempotency index, the single-flight and the lossy queue** are the design; the syntax is not.

```python
"""url_shortener_lld.py — the classes inside the HLD's boxes.

Design summary
--------------
Base62Encoder        : pure. Integer in, string out. No state, no I/O.
ShortCodeGenerator   : a strategy. `attempt` is part of the contract, because a
                       generator that ignores it spins the retry loop forever.
Collision policy     : the COUNTER cannot collide, which is why it is the
                       default. Randomness and hashing retry, and the retry is
                       BOUNDED — an unbounded loop on a correctness event is an
                       outage waiting for a bad seed.
UrlRepository        : insert() raises CodeTaken rather than returning a bool,
                       so the check and the write are one atomic operation.
Idempotency index    : by_url: {url_hash -> code}. The same long URL returns
                       the same short code, and the check-and-insert shares a
                       lock for the same reason the collision retry does.
CacheAsideStore      : read-through plus SINGLE-FLIGHT. On a miss for a hot
                       code, one caller loads and the rest wait for its result
                       instead of all hammering the database.
RedirectPolicy       : 301 vs 302 as an injected policy. 302 is the default
                       because a browser-cached 301 kills both analytics and
                       the ability to re-point a link.
ClickEventPublisher  : a BOUNDED queue that DROPS on overflow. A redirect must
                       never block on analytics; losing a click event is
                       strictly better than a slow redirect.
"""
from __future__ import annotations

import hashlib
import secrets
import threading
import time
from abc import ABC, abstractmethod
from dataclasses import dataclass, field, replace
from enum import Enum
from typing import Callable, Iterable, Optional


# --------------------------------------------------------------------------
# 1. Encoding — pure
# --------------------------------------------------------------------------

class Base62Encoder:
    """A base-N encoder; N is `len(alphabet)`, and 62 is the conventional N.

    Pure. The alphabet is a parameter because the DEFAULT strips the six
    look-alike characters — a short code is read aloud and typed by hand, and
    `0/O`, `1/l/I` are the pairs that break that. Stripping them leaves a
    56-character alphabet, so the default is honestly base56 even though the
    class is named for the general case; `FULL_ALPHABET` is the 62-character
    set when maximum density matters more than transcription.
    """

    FULL_ALPHABET = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ"

    # 62 minus 0, O, 1, l, I and o -> 56 characters.
    DEFAULT_ALPHABET = "23456789abcdefghijkmnpqrstuvwxyzABCDEFGHJKLMNPQRSTUVWXYZ"

    def __init__(self, alphabet: str = DEFAULT_ALPHABET) -> None:
        if len(alphabet) < 2:
            raise ValueError("the alphabet needs at least two characters")
        if len(set(alphabet)) != len(alphabet):
            raise ValueError("the alphabet has duplicate characters")
        self.alphabet = alphabet
        self._index = {ch: i for i, ch in enumerate(alphabet)}

    @property
    def base(self) -> int:
        return len(self.alphabet)

    def encode(self, number: int) -> str:
        if number < 0:
            raise ValueError("cannot encode a negative number")
        if number == 0:
            return self.alphabet[0]
        digits = []
        base = self.base
        while number > 0:
            number, remainder = divmod(number, base)
            digits.append(self.alphabet[remainder])
        return "".join(reversed(digits))

    def decode(self, text: str) -> int:
        if not text:
            raise ValueError("cannot decode an empty string")
        number = 0
        base = self.base
        for ch in text:
            if ch not in self._index:
                raise ValueError(f"{ch!r} is not in the alphabet")
            number = number * base + self._index[ch]
        return number

    def pad(self, text: str, width: int) -> str:
        """Left-pad to a fixed width. Only for display or for a fixed-length
        code space — `encode` itself is variable-length, and pretending
        otherwise is how off-by-one length bugs get in."""
        if len(text) > width:
            raise ValueError(f"{text!r} is longer than {width}")
        return self.alphabet[0] * (width - len(text)) + text


# --------------------------------------------------------------------------
# 2. Code format and validation
# --------------------------------------------------------------------------

class InvalidCode(Exception):
    pass


class CodeTaken(Exception):
    pass


class CodeExhausted(Exception):
    pass


@dataclass(frozen=True)
class CodeFormat:
    min_length: int = 4
    max_length: int = 16
    alphabet: str = Base62Encoder.DEFAULT_ALPHABET
    # A custom alias is typed by the person who chose it, so it uses the
    # PERMISSIVE alphabet. The look-alike problem does not exist for a string
    # its own author already knows by heart.
    ALIAS_ALPHABET: str = Base62Encoder.FULL_ALPHABET + "-_"
    reserved: frozenset[str] = frozenset({
        "api", "admin", "login", "logout", "static", "health", "metrics",
        "about", "help", "terms", "privacy", "favicon",
    })

    def validate(self, code: str) -> str:
        """For GENERATED codes: the stripped alphabet applies, because these
        are read aloud and transcribed by people who did not choose them."""
        # Reserved FIRST: "api" is reserved regardless of what the length rules
        # happen to be, and "that word is taken" is a more useful error than
        # "that word is too short" for a word that will never be allowed.
        if code.lower() in self.reserved:
            raise InvalidCode(f"{code!r} is reserved")
        if not (self.min_length <= len(code) <= self.max_length):
            raise InvalidCode(
                f"a code must be {self.min_length}-{self.max_length} characters, "
                f"got {len(code)}")
        bad = [ch for ch in code if ch not in self.alphabet]
        if bad:
            raise InvalidCode(f"invalid character(s): {''.join(sorted(set(bad)))}")
        return code

    def validate_alias(self, alias: str) -> str:
        """For USER-CHOSEN aliases: the permissive alphabet applies.

        This split is the point. Generated codes strip `0/O/1/l/I/o` because a
        stranger has to read them off a screen; refusing the alias "myalias"
        for its "l" would be an absurdity, since the author picked that string
        deliberately and will type it themselves. The rules that still apply
        are the reserved words and the character class, because those are about
        safety rather than transcription.
        """
        if alias.lower() in self.reserved:
            raise InvalidCode(f"{alias!r} is reserved")
        if not (self.min_length <= len(alias) <= self.max_length):
            raise InvalidCode(
                f"an alias must be {self.min_length}-{self.max_length} "
                f"characters, got {len(alias)}")
        bad = [ch for ch in alias if ch not in self.ALIAS_ALPHABET]
        if bad:
            raise InvalidCode(
                f"invalid character(s) in alias: {''.join(sorted(set(bad)))}")
        return alias

    def pad(self, code: str) -> str:
        """Left-fill to `min_length` with the alphabet's first character.

        This is where the format constrains the generator, and it belongs here
        rather than in the generator because a generator must not have to know
        the format. Padding preserves injectivity — base-N representation is
        unique, and left-padding to a fixed width is a bijection onto the
        fixed-width codes — so a counter's low values ("2", "3") still give
        distinct codes and the no-collision property survives.
        """
        if len(code) >= self.min_length:
            return code
        return self.alphabet[0] * (self.min_length - len(code)) + code


# --------------------------------------------------------------------------
# 3. Code generation — the strategy, and why the counter is different
# --------------------------------------------------------------------------

class ShortCodeGenerator(ABC):
    @abstractmethod
    def generate(self, url: str, attempt: int) -> str: ...


class CounterGenerator(ShortCodeGenerator):
    """A counter CANNOT collide, within one code space, because the same
    integer is never handed out twice. That is the whole reason it is the
    default: the retry loop exists for the generators that can collide, and
    with this one it never runs.

    `attempt` is ignored ON PURPOSE — and this is safe precisely because the
    counter is monotonic, so a retry gets a NEW number rather than the same
    one. A random generator that ignored `attempt` would return the same code
    forever; this one does not, because the input changed.
    """

    def __init__(self, encoder: Base62Encoder, start: int = 1,
                 width: int = 0) -> None:
        self.encoder = encoder
        self._next = start
        self._lock = threading.Lock()
        self.width = width

    def next_id(self) -> int:
        # The increment is the only shared mutable state in the generator
        # layer, and it is atomic.
        with self._lock:
            value = self._next
            self._next += 1
            return value

    def generate(self, url: str, attempt: int) -> str:
        code = self.encoder.encode(self.next_id())
        if self.width:
            code = self.encoder.pad(code, self.width)
        return code


class RandomGenerator(ShortCodeGenerator):
    """Uses `attempt` as a salt, so a retry is a genuinely different draw."""

    def __init__(self, encoder: Base62Encoder, length: int = 7) -> None:
        self.encoder = encoder
        self.length = length

    def generate(self, url: str, attempt: int) -> str:
        alphabet = self.encoder.alphabet
        return "".join(secrets.choice(alphabet) for _ in range(self.length))


class HashGenerator(ShortCodeGenerator):
    """Deterministic in the URL, salted by the attempt. Deterministic is a
    feature and a trap: it means the same URL yields the same code without an
    idempotency index, and it means a retry MUST change the salt or it returns
    the identical colliding code forever."""

    def __init__(self, encoder: Base62Encoder, length: int = 7) -> None:
        self.encoder = encoder
        self.length = length

    def generate(self, url: str, attempt: int) -> str:
        digest = hashlib.sha256(f"{url}|{attempt}".encode("utf-8")).digest()
        number = int.from_bytes(digest[:8], "big")
        code = self.encoder.encode(number)
        # Truncate from the LEFT, because the low-order digits of a hash are
        # the well-mixed ones; taking the high digits of a truncated encode
        # would bias the prefix.
        if len(code) > self.length:
            code = code[-self.length:]
        return self.encoder.pad(code, self.length)

# 4. The record and the repository
# --------------------------------------------------------------------------

@dataclass(frozen=True)
class UrlRecord:
    code: str
    long_url: str
    url_hash: str
    created_at: float
    expires_at: Optional[float] = None
    owner_id: Optional[str] = None

    def is_expired(self, now: float) -> bool:
        return self.expires_at is not None and now >= self.expires_at

    def with_long_url(self, new_url: str) -> "UrlRecord":
        """Re-pointing a link. It returns a NEW record rather than mutating,
        because the code's identity has not changed but its target has, and a
        reader holding the old record must not be changed underneath."""
        return replace(self, long_url=new_url,
                       url_hash=hash_url(new_url), created_at=self.created_at)


def hash_url(url: str) -> str:
    """Normalise before hashing: a trailing slash or a stray capital should not
    create a second code for the same destination."""
    normalised = url.strip()
    if "://" in normalised:
        scheme, _, rest = normalised.partition("://")
        normalised = f"{scheme.lower()}://{rest}"
    if normalised.endswith("/") and normalised.count("/") > 2:
        normalised = normalised.rstrip("/")
    return hashlib.sha256(normalised.encode("utf-8")).hexdigest()


class UrlRepository(ABC):
    @abstractmethod
    def insert(self, record: UrlRecord) -> None: ...
    @abstractmethod
    def find_by_code(self, code: str) -> Optional[UrlRecord]: ...
    @abstractmethod
    def find_by_url_hash(self, url_hash: str) -> Optional[UrlRecord]: ...
    @abstractmethod
    def delete(self, code: str) -> bool: ...


class InMemoryUrlRepository(UrlRepository):
    """Two indexes. `by_url` is the idempotency index and it is the one people
    forget: without it, "shorten this URL" twice produces two codes, and the
    second is a silent duplicate that splits the click analytics in half."""

    def __init__(self) -> None:
        self.by_code: dict[str, UrlRecord] = {}
        self.by_url: dict[str, str] = {}          # url_hash -> code
        self._lock = threading.Lock()

    def insert(self, record: UrlRecord) -> None:
        with self._lock:
            if record.code in self.by_code:
                raise CodeTaken(record.code)
            self.by_code[record.code] = record
            self.by_url.setdefault(record.url_hash, record.code)

    def insert_or_get(self, record: UrlRecord,
                      now: Optional[float] = None) -> tuple[UrlRecord, bool]:
        """The idempotent insert. One lock covers the lookup and the write,
        because a check-then-insert is a race in which two concurrent requests
        both find the URL absent and both insert.

        `now` is what makes expiry interact correctly with idempotency: if the
        code this URL already maps to has LAPSED, returning it would hand back
        a dead link forever. The lapsed record is retired and the index is
        taken over instead.
        """
        with self._lock:
            existing_code = self.by_url.get(record.url_hash)
            if existing_code is not None and existing_code in self.by_code:
                existing = self.by_code[existing_code]
                if now is None or not existing.is_expired(now):
                    return existing, False
                del self.by_code[existing_code]
            if record.code in self.by_code:
                raise CodeTaken(record.code)
            self.by_code[record.code] = record
            self.by_url[record.url_hash] = record.code
            return record, True

    def find_by_code(self, code: str) -> Optional[UrlRecord]:
        with self._lock:
            return self.by_code.get(code)

    def find_by_url_hash(self, url_hash: str) -> Optional[UrlRecord]:
        with self._lock:
            code = self.by_url.get(url_hash)
            return self.by_code.get(code) if code else None

    def delete(self, code: str) -> bool:
        with self._lock:
            record = self.by_code.pop(code, None)
            if record is None:
                return False
            # Only drop the URL index if it still points at this code — a
            # re-pointed link may have left it pointing elsewhere.
            if self.by_url.get(record.url_hash) == code:
                del self.by_url[record.url_hash]
            return True

    def update(self, record: UrlRecord) -> None:
        """Re-pointing. The URL INDEX must move too, or the old hash keeps
        pointing at this code while the new hash maps to nothing — which means
        shortening the new destination a second time would mint a SECOND code
        and split the analytics across the two."""
        with self._lock:
            previous = self.by_code.get(record.code)
            if previous is None:
                raise KeyError(f"no such code: {record.code}")
            if previous.url_hash != record.url_hash:
                if self.by_url.get(previous.url_hash) == record.code:
                    del self.by_url[previous.url_hash]
                self.by_url[record.url_hash] = record.code
            self.by_code[record.code] = record

class CacheStore(ABC):
    @abstractmethod
    def get(self, key: str) -> Optional[str]: ...
    @abstractmethod
    def set(self, key: str, value: str, ttl_seconds: int = 3600) -> None: ...
    @abstractmethod
    def delete(self, key: str) -> None: ...


class InMemoryCacheStore(CacheStore):
    def __init__(self, clock: Callable[[], float] = time.monotonic) -> None:
        self._data: dict[str, tuple[str, Optional[float]]] = {}
        self._lock = threading.Lock()
        self.clock = clock

    def get(self, key: str) -> Optional[str]:
        with self._lock:
            entry = self._data.get(key)
            if entry is None:
                return None
            value, expires_at = entry
            if expires_at is not None and self.clock() >= expires_at:
                del self._data[key]
                return None
            return value

    def set(self, key: str, value: str, ttl_seconds: int = 3600) -> None:
        with self._lock:
            expires = None if ttl_seconds <= 0 else self.clock() + ttl_seconds
            self._data[key] = (value, expires)

    def delete(self, key: str) -> None:
        with self._lock:
            self._data.pop(key, None)


class _Flight:
    """One in-progress load, and the callers waiting on it."""

    def __init__(self) -> None:
        self.event = threading.Event()
        self.value: Optional[str] = None
        self.error: Optional[BaseException] = None


class CacheAsideStore:
    """Read-through with SINGLE-FLIGHT.

    The HLD says "cache-aside, ~60x read amplification". One level down the
    interesting part is not the lookup, it is the MISS: a hot code that expires
    gets a thousand simultaneous misses, and without single-flight all thousand
    go to the database and the cache stampede is the outage, not the miss.

    The negative cache matters too: a code that does not exist is looked up
    repeatedly by scanners, and caching "absent" prevents that from being a
    database query per request. It uses a SHORT ttl, because the code may be
    created a second later.
    """

    MISS = "\x00__absent__"

    def __init__(self, repository: UrlRepository, cache: CacheStore,
                 ttl_seconds: int = 3600, negative_ttl_seconds: int = 30) -> None:
        self.repository = repository
        self.cache = cache
        self.ttl = ttl_seconds
        self.negative_ttl = negative_ttl_seconds
        self._flights: dict[str, _Flight] = {}
        self._lock = threading.Lock()
        self.loads = 0          # so a test can prove the single-flight worked

    def get(self, code: str) -> Optional[UrlRecord]:
        key = f"url:{code}"
        cached = self.cache.get(key)
        if cached is not None:
            return None if cached == self.MISS else self._decode(cached)

        # --- single-flight: one loader per key, everyone else waits ---
        with self._lock:
            flight = self._flights.get(code)
            leader = flight is None
            if leader:
                flight = _Flight()
                self._flights[code] = flight
        assert flight is not None

        if not leader:
            flight.event.wait()
            if flight.error is not None:
                raise flight.error
            return None if flight.value == self.MISS else (
                self._decode(flight.value) if flight.value else None)

        try:
            record = self.repository.find_by_code(code)
            self.loads += 1
            if record is None:
                self.cache.set(key, self.MISS, self.negative_ttl)
                flight.value = self.MISS
                return None
            self.cache.set(key, self._encode(record), self.ttl)
            flight.value = self._encode(record)
            return record
        except BaseException as exc:                       # noqa: BLE001
            flight.error = exc
            raise
        finally:
            with self._lock:
                self._flights.pop(code, None)
            flight.event.set()          # ALWAYS, including on failure

    def invalidate(self, code: str) -> None:
        self.cache.delete(f"url:{code}")

    @staticmethod
    def _encode(record: UrlRecord) -> str:
        expires = "" if record.expires_at is None else str(record.expires_at)
        return f"{record.long_url}\x1f{expires}"

    @staticmethod
    def _decode(blob: str) -> UrlRecord:
        long_url, _, expires = blob.partition("\x1f")
        return UrlRecord(code="", long_url=long_url, url_hash="", created_at=0.0,
                         expires_at=float(expires) if expires else None)

class RedirectPolicy(ABC):
    @abstractmethod
    def status(self, record: UrlRecord) -> int: ...


class AlwaysTemporary(RedirectPolicy):
    """302. The default, and the right default: a 301 is cached by the browser
    PERMANENTLY, so the click never reaches the server again and the analytics
    for that link stop on the second visit. It also makes the link impossible
    to re-point, because the browser no longer asks."""

    def status(self, record: UrlRecord) -> int:
        return 302


class PermanentForStatic(RedirectPolicy):
    """301 only where the destination genuinely cannot change and clicks are
    not billed — a versioned asset, a canonical host. The decision is data
    about the record, not a constant in the resolver."""

    def __init__(self, permanent_prefixes: Iterable[str] = ("/static/", "/assets/")) -> None:
        self.prefixes = tuple(permanent_prefixes)

    def status(self, record: UrlRecord) -> int:
        if any(record.long_url.endswith(p) or p in record.long_url
               for p in self.prefixes):
            return 301
        return 302


@dataclass(frozen=True)
class ClickEvent:
    code: str
    at: float
    referrer: str = ""
    user_agent_class: str = "unknown"

    def __str__(self) -> str:
        return f"{self.code} @{self.at:.0f} from {self.referrer or 'direct'}"


class ClickEventPublisher(ABC):
    @abstractmethod
    def publish(self, event: ClickEvent) -> bool: ...


class BoundedClickPublisher(ClickEventPublisher):
    """A BOUNDED queue that DROPS on overflow.

    This is the design decision worth defending. A redirect is on the critical
    path and a click event is not, so the queue must never make the caller
    wait: no blocking put, no unbounded growth. When the drain cannot keep up,
    the correct behaviour is to lose events and increment a counter that is
    alerted on — because the alternative, a redirect that blocks because
    analytics is behind, converts an analytics incident into a site outage.
    """

    def __init__(self, capacity: int = 10_000,
                 sink: Optional[Callable[[list[ClickEvent]], None]] = None,
                 clock: Callable[[], float] = time.monotonic) -> None:
        if capacity < 1:
            raise ValueError("capacity must be at least 1")
        self.capacity = capacity
        self._queue: list[ClickEvent] = []
        self._lock = threading.Lock()
        self._sink = sink if sink is not None else (lambda batch: None)
        self.clock = clock
        self.published = 0
        self.dropped = 0
        self.drained_batches = 0

    def publish(self, event: ClickEvent) -> bool:
        with self._lock:
            if len(self._queue) >= self.capacity:
                self.dropped += 1
                return False
            self._queue.append(event)
            self.published += 1
            return True

    def drain(self, max_batch: int = 500) -> int:
        """Called by a background worker. Takes a batch and hands it to the
        sink OUTSIDE the lock, so a slow sink cannot block publishers — which
        is the entire point of the queue."""
        with self._lock:
            if not self._queue:
                return 0
            batch = self._queue[:max_batch]
            del self._queue[:max_batch]
        self._sink(batch)
        self.drained_batches += 1
        return len(batch)

    @property
    def depth(self) -> int:
        with self._lock:
            return len(self._queue)

# 7. The resolver
# --------------------------------------------------------------------------

class Resolved(Enum):
    FOUND = "found"
    GONE = "gone"
    NOT_FOUND = "not_found"


@dataclass(frozen=True)
class RedirectResult:
    outcome: Resolved
    long_url: Optional[str] = None
    status: int = 404

    def __str__(self) -> str:
        return f"{self.status} {self.outcome.value}" + (
            f" -> {self.long_url}" if self.long_url else "")


class RedirectResolver:
    def __init__(self, store: CacheAsideStore, policy: RedirectPolicy,
                 publisher: ClickEventPublisher, fmt: CodeFormat,
                 clock: Callable[[], float] = time.monotonic) -> None:
        self.store = store
        self.policy = policy
        self.publisher = publisher
        self.fmt = fmt
        self.clock = clock

    def resolve(self, code: str, referrer: str = "") -> RedirectResult:
        # 1. Validate the FORMAT first. A malformed code cannot exist in the
        #    store, so this is a pure check that avoids a lookup — and it stops
        #    scanners from reaching the cache with junk keys at all.
        try:
            self.fmt.validate(code)
        except InvalidCode:
            return RedirectResult(Resolved.NOT_FOUND, status=404)

        record = self.store.get(code)
        if record is None:
            return RedirectResult(Resolved.NOT_FOUND, status=404)

        # 2. Expiry is checked on READ, not by a reaper. A reaper that has not
        #    run yet must not serve a lapsed link, so the read is the authority
        #    and the deletion is housekeeping.
        if record.is_expired(self.clock()):
            self.store.invalidate(code)
            return RedirectResult(Resolved.GONE, status=410)

        status = self.policy.status(record)

        # 3. Publish AFTER the decision, and never let it affect the result.
        #    The queue is bounded and lossy, so this cannot fail the redirect.
        self.publisher.publish(ClickEvent(code=code, at=self.clock(),
                                          referrer=referrer))
        return RedirectResult(Resolved.FOUND, record.long_url, status)

class UrlShortenerService:
    def __init__(self, repository: InMemoryUrlRepository,
                 generator: ShortCodeGenerator, fmt: CodeFormat,
                 cache: Optional[CacheAsideStore] = None,
                 max_attempts: int = 5,
                 clock: Callable[[], float] = time.monotonic) -> None:
        self.repository = repository
        self.generator = generator
        self.fmt = fmt
        self.max_attempts = max_attempts
        self.clock = clock
        if cache is None:
            cache = CacheAsideStore(repository, InMemoryCacheStore(clock=clock))
        self.store = cache

    def shorten(self, long_url: str, alias: Optional[str] = None,
                ttl_seconds: Optional[int] = None,
                owner_id: Optional[str] = None) -> tuple[UrlRecord, bool]:
        """Returns (record, created). `created` is False when this was an
        idempotent hit — the caller can then answer 200 instead of 201."""
        if not long_url or not long_url.strip():
            raise ValueError("a URL is required")

        url_hash = hash_url(long_url)
        now = self.clock()
        expires_at = None if ttl_seconds is None else now + ttl_seconds

        # --- LOOP 1: idempotency. Checked first, because if this URL already
        #     has a code, no generation should happen at all.
        if alias is None:
            existing = self.repository.find_by_url_hash(url_hash)
            if existing is not None and not existing.is_expired(now):
                return existing, False

        if alias is not None:
            # A custom alias is NOT idempotent: two people may want the same
            # alias for different URLs, and the second must be told it is taken
            # rather than silently handed the first one's link.
            self.fmt.validate_alias(alias)
            record = UrlRecord(alias, long_url, url_hash, now, expires_at, owner_id)
            inserted = self.repository.insert_or_get(record, now)
            if not inserted[1]:
                raise CodeTaken(alias)
            return inserted[0], True

        # --- LOOP 2: the BOUNDED collision retry ---
        last_error: Optional[BaseException] = None
        for attempt in range(self.max_attempts):
            code = self.generator.generate(long_url, attempt)
            # The format's minimum length is enforced HERE. A counter's first
            # values encode to one character, and the generator must not have
            # to know that the format demands four.
            code = self.fmt.pad(code)
            self.fmt.validate(code)
            record = UrlRecord(code, long_url, url_hash, now, expires_at, owner_id)
            try:
                stored, created = self.repository.insert_or_get(record, now)
            except CodeTaken as exc:
                last_error = exc
                continue          # try the next candidate
            if not created:
                # Another thread won the idempotency race for this URL while we
                # were generating. Return theirs, not ours.
                return stored, False
            self.store.cache.set(f"url:{code}",
                                 CacheAsideStore._encode(record), 3600)
            return stored, True

        raise CodeExhausted(
            f"could not allocate a code in {self.max_attempts} attempts "
            f"(last: {last_error})")

    def resolve(self, code: str, referrer: str = "") -> RedirectResult:
        return self.resolver().resolve(code, referrer)

    def resolver(self) -> RedirectResolver:
        return RedirectResolver(self.store, AlwaysTemporary(),
                                BoundedClickPublisher(), self.fmt,
                                clock=self.clock)

    def delete(self, code: str) -> bool:
        deleted = self.repository.delete(code)
        if deleted:
            self.store.invalidate(code)
        return deleted

    def repoint(self, code: str, new_url: str) -> UrlRecord:
        """Changing where a link goes. This is the operation a 301 makes
        impossible for anyone who already visited, which is the practical
        argument for 302."""
        record = self.repository.find_by_code(code)
        if record is None:
            raise KeyError(f"no such code: {code}")
        updated = record.with_long_url(new_url)
        self.repository.update(updated)
        self.store.invalidate(code)
        return updated

def _check(name: str, condition: bool) -> None:
    print(f"{'PASS' if condition else 'FAIL'}  {name}")
    if not condition:
        raise SystemExit(1)


def _raises(exc_type, fn) -> Optional[str]:
    try:
        fn()
    except exc_type as exc:
        return str(exc)
    return None

    res = svc.resolve(rec.code)
    _check("resolving finds the URL", res.long_url == "https://example.com/a")
    _check("and returns 302 by default", res.status == 302)
    _check("an unknown code is 404", svc.resolve("zzzzzzz").status == 404)
    _check("a malformed code is 404 without a lookup",
           svc.resolve("a!").status == 404)
    _check("a reserved code is 404", svc.resolve("api").status == 404)

    # --- 9. the redirect policy is data, not a constant ---
    static_rec = UrlRecord("s1", "https://cdn.example/static/app.js", "h", 0.0)
    dynamic_rec = UrlRecord("d1", "https://example.com/page", "h", 0.0)
    policy = PermanentForStatic()
    _check("a static asset gets 301", policy.status(static_rec) == 301)
    _check("a dynamic page still gets 302", policy.status(dynamic_rec) == 302)
    _check("the default policy is 302 for everything",
           AlwaysTemporary().status(static_rec) == 302)

    # --- 10. expiry is checked on read ---
    now = {"t": 1000.0}
    repo_exp = InMemoryUrlRepository()
    svc_exp = UrlShortenerService(repo_exp, CounterGenerator(enc), CodeFormat(),
                                  clock=lambda: now["t"])
    exp_rec, _ = svc_exp.shorten("https://example.com/lapsing", ttl_seconds=60)
    _check("the record carries an expiry", exp_rec.expires_at == 1060.0)
    _check("it resolves before the deadline",
           svc_exp.resolve(exp_rec.code).status == 302)
    now["t"] = 1061.0
    gone = svc_exp.resolve(exp_rec.code)
    _check("and is 410 Gone after it", gone.status == 410)
    _check("which is distinguishable from a code that never existed",
           gone.outcome is not Resolved.NOT_FOUND)
    _check("an expired URL can be shortened again (no idempotent hit)",
           svc_exp.shorten("https://example.com/lapsing")[1] is True)

    # --- 11. SINGLE-FLIGHT: the cache stampede ---
    slow_repo = InMemoryUrlRepository()
    slow_repo.insert(UrlRecord("hotcode", "https://example.com/hot",
                               hash_url("https://example.com/hot"), 0.0))
    store = CacheAsideStore(slow_repo, InMemoryCacheStore())

    original_find = slow_repo.find_by_code
    delay = {"on": True}

    def slow_find(code: str):
        if delay["on"]:
            time.sleep(0.05)         # a slow database
        return original_find(code)

    slow_repo.find_by_code = slow_find       # type: ignore[assignment]

    results: list[Optional[UrlRecord]] = []
    results_lock = threading.Lock()
    start = threading.Barrier(20)

    def hammer() -> None:
        start.wait()
        record = store.get("hotcode")
        with results_lock:
            results.append(record)

    threads = [threading.Thread(target=hammer) for _ in range(20)]
    for t in threads:
        t.start()
    for t in threads:
        t.join()
    _check("all 20 concurrent readers got the record",
           len(results) == 20 and all(r is not None for r in results))
    _check("but the repository was loaded EXACTLY ONCE", store.loads == 1)

    # The contrast that makes the number mean something: with the entry warm,
    # there is no load at all. (20 loads is what the unflighted version would
    # report — the assertion above is only interesting because it is 1.)
    store.loads = 0
    store.get("hotcode")
    _check("a warm cache serves without touching the repository", store.loads == 0)

    # --- 12. the negative cache ---
    neg_store = CacheAsideStore(slow_repo, InMemoryCacheStore())
    for _ in range(5):
        neg_store.get("nosuchcode")
    _check("five lookups of an absent code cost ONE database read",
           neg_store.loads == 1)
    _check("and the absent entry is cached",
           neg_store.cache.get("url:nosuchcode") == CacheAsideStore.MISS)

    # --- 13. the click publisher is bounded and lossy, not blocking ---
    batches: list[list[ClickEvent]] = []
    pub = BoundedClickPublisher(capacity=5, sink=batches.append,
                                clock=lambda: 0.0)
    accepted = [pub.publish(ClickEvent(f"c{i}", 0.0)) for i in range(8)]
    _check("the first five are accepted", accepted[:5] == [True] * 5)
    _check("and the rest are DROPPED, not blocked", accepted[5:] == [False] * 3)
    _check("the queue depth never exceeds capacity", pub.depth == 5)
    _check("the drop is counted so it can be alerted on", pub.dropped == 3)
    drained = pub.drain()
    _check("draining takes the whole batch", drained == 5 and pub.depth == 0)
    _check("and the sink received it", len(batches) == 1 and len(batches[0]) == 5)
    _check("publishing works again after a drain",
           pub.publish(ClickEvent("after", 0.0)) is True)
    _check("a zero capacity is refused",
           _raises(ValueError, lambda: BoundedClickPublisher(capacity=0)) is not None)

    # A publish that fills the queue must not touch the resolution result.
    rsv = svc.resolver()
    rsv.publisher = BoundedClickPublisher(capacity=1)
    _check("the first resolve publishes", rsv.resolve(rec.code).status == 302)
    _check("the second still resolves despite a full queue",
           rsv.resolve(rec.code).status == 302)
    _check("and the publisher recorded a drop",
           rsv.publisher.dropped == 1)     # type: ignore[attr-defined]

    # --- 14. delete invalidates the cache ---
    _check("the code resolves before deletion", svc.resolve(rec.code).status == 302)
    _check("deleting reports success", svc.delete(rec.code) is True)
    _check("and it is 404 afterwards", svc.resolve(rec.code).status == 404)
    _check("deleting again reports failure", svc.delete(rec.code) is False)
    _check("the URL index was cleaned up",
           repo.find_by_url_hash(hash_url("https://example.com/a")) is None)

    # --- 15. re-pointing a link ---
    target, _ = svc.shorten("https://example.com/before")
    moved = svc.repoint(target.code, "https://example.com/after")
    _check("the code is unchanged", moved.code == target.code)
    _check("the destination changed",
           svc.resolve(target.code).long_url == "https://example.com/after")
    _check("the new URL is now the idempotent target",
           svc.shorten("https://example.com/after")[0].code == target.code)
    _check("re-pointing an unknown code raises",
           _raises(KeyError, lambda: svc.repoint("zzzzzzz", "https://x.example"))
           is not None)

    # --- 16. the retry loop is bounded and reports what happened ---
    class CollidingGenerator(ShortCodeGenerator):
        """Returns the SAME code on attempts 0 and 1, then a fresh one. This is
        what a real collision looks like: a generator that is deterministic
        enough to repeat itself occasionally."""

        def __init__(self, taken: str) -> None:
            self.taken = taken
            self.calls = 0

        def generate(self, url: str, attempt: int) -> str:
            self.calls += 1
            # "fine2" is 5 characters and contains no stripped look-alike, so
            # it passes CodeFormat. A 3-character code would fail the length
            # rule and raise InvalidCode instead of exercising the collision
            # path this test is about.
            return self.taken if attempt < 2 else f"fine{attempt}"

    repo_c = InMemoryUrlRepository()
    repo_c.insert(UrlRecord("CLASH", "https://taken.example",
                            hash_url("https://taken.example"), 0.0))
    gen_c = CollidingGenerator("CLASH")
    svc_c = UrlShortenerService(repo_c, gen_c, CodeFormat(), max_attempts=5)
    won, created_c = svc_c.shorten("https://fresh.example")
    _check("the retry loop recovers from a collision", created_c is True)
    _check("and the winning code is not the colliding one", won.code != "CLASH")
    _check("after exactly three attempts", gen_c.calls == 3)

    # --- 17. two threads shortening the same URL concurrently ---
    repo_r = InMemoryUrlRepository()
    svc_r = UrlShortenerService(repo_r, CounterGenerator(enc), CodeFormat())
    race_start = threading.Barrier(12)
    race_codes: list[str] = []
    race_lock = threading.Lock()

    def shorten_same() -> None:
        race_start.wait()
        record, _ = svc_r.shorten("https://example.com/contended")
        with race_lock:
            race_codes.append(record.code)

    racers = [threading.Thread(target=shorten_same) for _ in range(12)]
    for t in racers:
        t.start()
    for t in racers:
        t.join()
    _check("twelve concurrent shortenings of one URL produce ONE code",
           len(set(race_codes)) == 1)
    _check("and the repository has exactly one record",
           len(repo_r.by_code) == 1)

    print("\nall checks passed")
```

**What to point at:**

- `HashGenerator.generate` mixes `attempt` into the digest — the contract that makes the retry terminate. The demo includes a `BrokenGenerator` that ignores it and **proves the loop fails loudly** rather than spinning.
- `InMemoryUrlRepository.insert_or_get` does the idempotency lookup and the write under **one lock**, and the demo races twelve threads at a barrier to show one code.
- `CacheAsideStore.get` is mostly single-flight machinery: the `_Flight` registry, the leader/follower split, and `flight.event.set()` in a `finally` so a failed loader cannot deadlock the waiters. The demo proves **20 concurrent readers → 1 database load**.
- `BoundedClickPublisher.publish` returns `False` on overflow and never blocks; `drain` hands the batch to the sink **outside** the lock so a slow sink cannot block publishers.
- `hash_url` normalises before hashing, so `…/a` and `…/a/` share a code — the demo asserts it.

## 6. Concurrency & thread-safety

| Hazard | What goes wrong | Fix |
|---|---|---|
| **Two requests shorten the same URL** | Both find no existing code, both generate, **two codes for one destination**, and the analytics split | `insert_or_get`: the idempotency lookup and the write under one lock; the loser returns the winner's record |
| **Two requests draw the same random code** | The second `insert` raises `CodeTaken`; that is the *expected* path, not an error | The bounded retry, plus `attempt` in the generator's contract |
| **A generator that ignores `attempt`** | The retry loop returns the same colliding code forever and spins to the bound | The contract in §4 and `BrokenGenerator` in the demo — it fails loudly |
| **The counter incremented non-atomically** | Two threads get the same integer, so the "cannot collide" generator collides | `CounterGenerator.next_id` holds a lock over read-and-increment |
| **A cache stampede on a hot code** | A thousand simultaneous misses all hit the database | Single-flight: one leader loads, the rest wait on the `Event` |
| **A loader that raises while others wait** | The waiters block forever on an `Event` that is never set | `flight.event.set()` in a `finally`; the follower re-raises the leader's error |
| **A malformed code hitting the cache** | Scanners fill the cache with junk keys and evict the hot ones | Format validation happens **before** the lookup |
| **An expired code still served** | A reaper that has not run yet leaves a lapsed link live | Expiry is checked on read; the read is the authority |
| **Analytics blocking the redirect** | A redirect times out because the event queue's consumer is behind | The queue is bounded and lossy; `publish` never blocks and never raises |
| **A slow sink blocking publishers** | `drain` holds the queue lock while the sink writes | The batch is taken under the lock and handed to the sink outside it |
| **A `dict` mutated during iteration** | A `RuntimeError` at exactly the wrong moment | Every repository and cache method holds the lock |
| **Multi-process deployment** | Two processes have two counters and two idempotency indexes | See below — a range allocator and a unique index in the store |

### The distributed version of the two loops

```python
class RangeAllocator:
    """The counter, when there is more than one process.

    Each process leases a BLOCK of integers — say 10,000 — and hands them out
    locally with no coordination at all. Only when the block is exhausted does
    it talk to the store again. That is the whole trick: the shared mutable
    state is touched once per block instead of once per code, so the contention
    drops by the block size.

    The cost is that ids are handed out in blocks per process, so codes are no
    longer globally ordered by creation time. Nothing in this design depends on
    that, which is why the trade is available — but a design that used the code
    as a timestamp proxy would break here.
    """

    def __init__(self, store, block_size: int = 10_000) -> None:
        self.store = store
        self.block_size = block_size
        self._next = 0
        self._limit = 0
        self._lock = threading.Lock()

    def next_id(self) -> int:
        with self._lock:
            if self._next >= self._limit:
                # One round trip per block, not per code.
                self._next = self.store.reserve_range(self.block_size)
                self._limit = self._next + self.block_size
            value = self._next
            self._next += 1
            return value
```

**And the idempotency index across processes.** The in-process lock becomes a **unique index on `url_hash`** in the store: `INSERT … ON CONFLICT (url_hash) DO NOTHING RETURNING code`. If the insert returns a row, this request created the code; if it returns nothing, somebody else did and the code is fetched by the hash. That is the same check-and-insert, expressed as a constraint rather than a mutex — and the important part is that the *database* is enforcing it, because a second process cannot see the first's lock.

## 7. Extensibility — the standard follow-ups, with real designs

### 7.1 "Add per-link analytics"

The publisher already emits the events; this is the aggregation, and the design point is that it must be **independent of the redirect path**:

```python
class ClickAggregator:
    """Consumes the publisher's batches. In production this is a stream job;
    here it demonstrates that the aggregation can be rebuilt from the event log
    and therefore does not need to be correct in real time."""

    def __init__(self) -> None:
        self.by_code: dict[str, int] = {}
        self.by_referrer: dict[str, dict[str, int]] = {}
        self._lock = threading.Lock()

    def consume(self, batch: list[ClickEvent]) -> None:
        with self._lock:
            for event in batch:
                self.by_code[event.code] = self.by_code.get(event.code, 0) + 1
                refs = self.by_referrer.setdefault(event.code, {})
                key = event.referrer or "direct"
                refs[key] = refs.get(key, 0) + 1

    def clicks(self, code: str) -> int:
        with self._lock:
            return self.by_code.get(code, 0)

    def referrers(self, code: str) -> dict[str, int]:
        with self._lock:
            return dict(self.by_referrer.get(code, {}))
```

The invariant worth asserting: **the aggregator's total equals the publisher's `published` minus `dropped`** — which is what makes the drop counter an operational metric rather than a curiosity.

### 7.2 "Rate-limit creation per API key"

This is a straight composition with [the rate limiter](../../LLD/problems/11-rate-limiter.md) — the LLD point is that the limiter is a **decorator on the service**, not a branch inside it:

```python
class RateLimitedShortener:
    """Wraps the façade. `shorten` checks the limiter first and raises, so the
    service itself knows nothing about quotas — the same reasoning as the
    rate limiter's own file, where the algorithm is a strategy and the
    distributed counter is a separate concern."""

    def __init__(self, inner: UrlShortenerService, limiter, key_fn) -> None:
        self.inner = inner
        self.limiter = limiter
        self.key_fn = key_fn

    def shorten(self, long_url: str, **kwargs):
        key = self.key_fn(long_url, kwargs.get("owner_id"))
        decision = self.limiter.check(key)
        if not decision.allowed:
            raise PermissionError(
                f"creation quota exhausted; retry in {decision.retry_after:.0f}s")
        return self.inner.shorten(long_url, **kwargs)
```

### 7.3 "Custom aliases, with an ownership rule"

Who owns an alias, and what happens when the owner leaves:

```python
class AliasPolicy(ABC):
    @abstractmethod
    def may_claim(self, alias: str, owner_id: Optional[str],
                  existing: Optional[UrlRecord]) -> bool: ...


class FirstComeAliasPolicy(AliasPolicy):
    def may_claim(self, alias, owner_id, existing) -> bool:
        return existing is None


class OwnerReclaimAliasPolicy(AliasPolicy):
    """An alias whose owner is the same user can be re-pointed; anyone else is
    refused. This is the rule that makes 'my brand link' possible without
    making squatting permanent — and it is a policy object because the rule
    differs per product."""

    def may_claim(self, alias, owner_id, existing) -> bool:
        if existing is None:
            return True
        return owner_id is not None and existing.owner_id == owner_id
```

### 7.4 "Bulk shortening"

The design point: **idempotency has to survive a batch**, and a partially-applied batch needs a decision.

```python
@dataclass(frozen=True)
class BulkResult:
    records: tuple[UrlRecord, ...]
    created: tuple[bool, ...]
    errors: tuple[tuple[int, str], ...]     # (index, message)

    @property
    def ok(self) -> bool:
        return not self.errors


def bulk_shorten(service: UrlShortenerService, urls: list[str],
                 all_or_nothing: bool = False) -> BulkResult:
    """`all_or_nothing` is the interesting parameter. Without a transaction the
    honest answer is that a batch is best-effort and the caller gets per-item
    results — an all-or-nothing batch needs a store that can roll back, and
    pretending otherwise produces a batch that reports success having written
    half the rows."""
    records: list[UrlRecord] = []
    created: list[bool] = []
    errors: list[tuple[int, str]] = []
    for index, url in enumerate(urls):
        try:
            record, was_created = service.shorten(url)
        except (InvalidCode, CodeExhausted, ValueError) as exc:
            errors.append((index, str(exc)))
            if all_or_nothing:
                return BulkResult((), (), tuple(errors))
            continue
        records.append(record)
        created.append(was_created)
    return BulkResult(tuple(records), tuple(created), tuple(errors))
```

### 7.5 "A short code that leaks the destination"

A real security follow-up: sequential counter codes are **enumerable**, so anybody can walk the space and read every link.

```python
class ObfuscatingGenerator(ShortCodeGenerator):
    """Wraps the counter's output in a reversible permutation so the codes are
    not sequential, without giving up the no-collision property.

    A Feistel round on the integer is the standard trick: it is a bijection, so
    distinct inputs still give distinct outputs, and it is reversible, so a
    code can be turned back into an id for support. This is the answer to
    "your codes are enumerable" that does not cost the collision guarantee —
    as opposed to switching to random codes, which reintroduces collisions.
    """

    def __init__(self, encoder: Base62Encoder, key: int, rounds: int = 4) -> None:
        self.encoder = encoder
        self.key = key
        self.rounds = rounds

    def _permute(self, value: int) -> int:
        left, right = value >> 16, value & 0xFFFF
        for round_index in range(self.rounds):
            mixed = (right * 0x9E3779B1 + self.key + round_index) & 0xFFFFFFFF
            mixed ^= mixed >> 15
            left, right = right, left ^ (mixed & 0xFFFF)
        return ((right << 16) | left) & 0xFFFFFFFF

    def generate(self, url: str, attempt: int) -> str:
        # attempt is ignored: the permutation is a bijection, so a fresh id
        # always yields a fresh code.
        return self.encoder.encode(self._permute(self.encoder.decode(
            self.encoder.encode(attempt + 1))))
```

*(The honest caveat to state: this is a sketch of the technique, not a vetted cipher — the real system uses a reviewed format-preserving encryption, and the design point is the reversal of the trade-off, not the round function.)*

## 8. Failure modes & edge cases

| # | Case | What a naive implementation does | Correct behaviour |
|---|---|---|---|
| 1 | **The same URL shortened twice** | Two codes; analytics split in half | The idempotency index on `url_hash` |
| 2 | **Check-then-insert for idempotency** | Two concurrent requests both create | One lock over the lookup and the write |
| 3 | **A generator that ignores `attempt`** | The retry loop spins to the bound on every collision | `attempt` is in the contract; the demo proves the failure |
| 4 | **An unbounded retry loop** | A bad seed hangs a request forever | `max_attempts`, then `CodeExhausted` |
| 5 | **`insert` returning a bool** | The collision is ignored and two records share a code | `insert` raises `CodeTaken` |
| 6 | **A cache stampede** | Every concurrent miss hits the database | Single-flight |
| 7 | **A loader that raises** | Waiters block forever on an unset `Event` | `set()` in a `finally`; the error propagates |
| 8 | **Junk codes reaching the cache** | Scanner traffic evicts hot keys | Format validation before the lookup |
| 9 | **A negative cache with a long TTL** | A code created a second later stays "absent" for an hour | A short negative TTL |
| 10 | **301 on a link you may need to re-point** | Browsers never ask again; the analytics stop and the link is frozen | 302 by default; 301 as an explicit policy |
| 11 | **Expiry enforced by a reaper only** | A lapsed link is served until the reaper runs | Expiry checked on read; a lapsed code is `410` |
| 12 | **`410` returned as `404`** | The user cannot tell a lapsed link from a typo | Distinct outcomes; a test asserts they differ |
| 13 | **Analytics blocking the redirect** | The redirect times out when the consumer lags | A bounded, lossy queue |
| 14 | **An unbounded event queue** | Memory grows until the process dies during the incident that made it grow | Bounded, with a drop counter to alert on |
| 15 | **A slow sink holding the queue lock** | Publishers block on the consumer | The batch is taken under the lock, handed over outside it |
| 16 | **Codes that are enumerable** | Anybody walks the counter and reads every link | A format-preserving permutation (§7.5) |
| 17 | **A custom alias colliding with a route** | `/api` becomes a redirect and breaks the app | A reserved-word denylist, checked before generation |
| 18 | **A trailing slash creating a second code** | `/a` and `/a/` get different codes and split the clicks | Normalise before hashing |
| 19 | **Deleting but not invalidating the cache** | The link keeps working for the TTL | `CacheAsideStore.invalidate` on delete |
| 20 | **A stale cache entry after re-pointing** | The old destination is served until the TTL | Invalidate on update, and prefer a short TTL for mutable links |
| 21 | **A code of variable length assumed fixed** | Off-by-one padding bugs | `encode` is variable-length; `pad` is separate and explicit |
| 22 | **Two processes, two counters** | Both hand out code 1 | A range allocator, and a unique index for idempotency |

**The three to volunteer:** #3 (the generator's contract — it is the bug that makes the retry loop useless), #6 (the stampede — the miss is not the problem, the simultaneous miss is), and #13 (analytics must not be able to break a redirect).

## 9. Design patterns used, and why

| Pattern | Where | Why it is right here | What it costs |
|---|---|---|---|
| **Strategy** | `ShortCodeGenerator` ×3, `RedirectPolicy` ×2, `AliasPolicy` in §7 | Generation and redirect semantics are the two things that change for product reasons | Two more injected collaborators |
| **Repository** | `UrlRepository` | Two indexes and an atomic insert belong behind one interface | An abstraction over a `dict` |
| **Decorator** | `CacheAsideStore` wraps `UrlRepository`; `RateLimitedShortener` wraps the service | Caching and quotas are cross-cutting and must be composable and removable | A wrapper whose miss path is the interesting code |
| **Ports & Adapters** | `CacheStore`, `ClickEventPublisher` | Redis and Kafka are adapters; the single-flight and drop logic stay testable | Two interfaces over small things |
| **Value Object** | `UrlRecord`, `ClickEvent`, `CodeFormat`, `RedirectResult` | Frozen, hashable, safe to cache and to log | An allocation per record |
| **Façade** | `UrlShortenerService` | Callers get three verbs | It owns the two loops, so it is not a thin pass-through |
| **Policy** | `AliasPolicy`, and the redirect status | The rule is data the caller can replace | An extra object for a one-line rule |
| **Singleton** | *Deliberately rejected* | A global encoder or counter makes two tests interfere | — |
| **Observer (in the aggregate)** | *Deliberately absent* | The publisher is an explicit call at a known point, not a subscription — a subscriber that throws must not fail a redirect | The call site must be maintained |

**The sentence to give:** *"Strategy for the generator and the redirect status, because those are the two product decisions; Decorator for caching and rate limiting, because they are cross-cutting and must be removable; a port for the cache and the publisher so the in-memory versions are first-class and the interesting logic — single-flight, the drop policy — is testable without a network. I would not use an observer for click events: a synchronous publish at a known point is easier to reason about, and the failure mode of a subscriber is contained rather than propagated."*

## 10. Trade-offs

| Decision | Choice made here | Buys | Costs |
|---|---|---|---|
| **Counter generator by default** | Yes | Collisions are impossible, so the retry loop never runs | Sequential, enumerable codes — fixed by §7.5 at the cost of a permutation |
| **Bounded collision retry** | Yes | A collision cannot become an outage | A legitimate collision beyond the bound fails the request |
| **`insert` raises on collision** | Yes | It cannot be ignored | A try/except in the caller |
| **Idempotency index on `url_hash`** | Yes | One URL, one code | An extra index, and normalisation rules that must be stable |
| **Custom aliases are not idempotent** | Yes | Two users cannot silently share an alias | A second `shorten` with the same alias is an error rather than a no-op |
| **Single-flight caching** | Yes | A hot miss costs one load, not a thousand | A `_Flight` registry per key, and a failure path to get right |
| **Short negative TTL** | Yes | Scanner traffic does not reach the database | A just-created code may be "absent" for up to 30s in a rare race |
| **302 by default** | Yes | Clicks are observable and links can be re-pointed | One extra request per visit |
| **Expiry checked on read** | Yes | A lapsed link is never served | A clock comparison per read |
| **Bounded, lossy click queue** | Yes | A redirect cannot fail because analytics is behind | Click counts are approximate under load |
| **Publish after the decision** | Yes | A publisher failure cannot change the response | — |
| **Format check before lookup** | Yes | Junk traffic never reaches the cache | Malformed custom aliases are impossible by construction |
| **In-memory repository** | Yes, with the distributed path shown | The model is testable in isolation | The range allocator and unique index are required before scaling out |

**The trade to name unprompted:** *"A lossy click queue means the click count is approximate under load, and I would defend it: the alternative is back-pressure onto the redirect path, which converts an analytics backlog into a site outage. The drop counter exists so the loss is visible and alertable rather than silent — an approximation you can measure is a different thing from a number that is quietly wrong."*

## 11. Q&A

**Q1. Why is the counter generator preferred if randomness is simpler?**
Because it moves collisions from a runtime event to a design fact. A counter is injective — it never hands out the same integer twice — so `insert` cannot raise `CodeTaken` from a collision, the retry loop never runs, and the failure mode simply does not exist. Randomness has a birthday-bound collision rate that is small but nonzero and, crucially, *unpredictable in production*, so it needs a retry loop that has to be tested and bounded. The counter's cost is that the codes are sequential and therefore enumerable, which is a real problem — and the answer is §7.5: a format-preserving permutation keeps the bijection while destroying the sequence, which is strictly better than switching to random codes and reintroducing collisions.

**Q2. Where exactly does the collision retry live, and what makes it correct?**
In `UrlShortenerService.shorten`, and correctness is three properties. It is **bounded**: `max_attempts`, then `CodeExhausted` — an unbounded loop on a correctness event is an outage waiting for a bad seed. The generator **uses `attempt`**: that is why it is in the contract, and the demo includes a `BrokenGenerator` that ignores it to show the loop exhausting rather than recovering, because that failure is silent in production until a collision happens. And it **relies on `insert` raising** rather than an `exists()` check, because a check-then-insert has a window where two requests both find the code free and both write.

**Q3. How does idempotency actually work here?**
Two indexes: `by_code` for lookup and `by_url` for idempotency. `shorten` computes a **normalised** hash of the long URL, checks `by_url` first, and returns the existing record if there is one — so the same URL never generates a code at all. The subtlety is that the check and the insert must be atomic, which is `insert_or_get`'s single lock: two requests that both find the URL absent and both insert have produced two codes for one destination, which is the exact failure the index exists to prevent. The demo races twelve threads on one URL and asserts one code — and the loser returns the *winner's* record, which is the behaviour that makes the endpoint safe to retry.

**Q4. Why does `hash_url` normalise before hashing?**
Because `https://example.com/a` and `https://example.com/a/` are the same destination, and if they hash differently the idempotency index does not fire and the user gets two codes for one link — with the click analytics split between them, which is worse than the duplicate itself because nobody notices. It lowercases the scheme and strips a trailing slash on a path with more than one segment. The rule has to be **stable and documented**, because it is effectively an equality relation on URLs and changing it invalidates every existing index entry.

**Q5. Explain single-flight and why the miss is the interesting part.**
The HLD says cache-aside with high read amplification. One level down the problem is not the hit path, it is the miss on a *hot* key: when a popular code expires, every request in flight misses simultaneously, and they all go to the database at once — a cache stampede, where the miss is not slow but the thousand simultaneous misses are. Single-flight fixes it by electing one loader per key: the first caller becomes the leader and creates a `_Flight`, the rest find it and wait on its `Event` for the leader's result. They do not each fetch. The two details that are easy to get wrong are `event.set()` in a `finally`, so a loader that raises cannot leave its waiters blocked forever, and propagating the leader's error to the followers so they do not silently return `None` for a temporary failure. The demo asserts twenty concurrent readers produce **one** database load.

**Q6. Why a negative cache, and why a short TTL?**
Because a code that does not exist is requested repeatedly — by scanners, by broken links, by a client retrying — and without a negative entry each of those is a database query for something that will never be there. With it, the first miss is a query and the rest are cache hits. The TTL must be **short**, around thirty seconds, because the negative entry is a claim that can become false: a code created a moment later is "absent" as far as the cache is concerned, and a 30-second staleness on a freshly created link is a real race. The alternative — invalidating the negative entry on creation — is possible but means the create path has to know about the negative key, which couples the two paths for a rare case.

**Q7. 301 or 302, and why is this an LLD question rather than an HLD one?**
302, by default. A 301 is cached by the browser **permanently**, so after the first visit the browser never asks the server again — which means the click is invisible to analytics, and the link can never be re-pointed because the browser will not consult the server. In HLD terms it is "a caching decision"; one level down it is a specific object, `RedirectPolicy`, because which links may be permanent is a per-record decision: a versioned static asset can safely be 301 because its destination genuinely cannot change, while a marketing link must be 302 because it will be re-pointed and its clicks are the product. Making it a policy object rather than a constant is what lets that distinction exist.

**Q8. Why does the click publisher drop events instead of blocking?**
Because the redirect and the click event have different reliability requirements and they are on the same code path. A redirect is the user's page load; a click event is analytics. If the queue applies back-pressure — a blocking put, or unbounded growth — then a lagging analytics consumer either slows every redirect or grows the queue until the process dies during the busy period that made it lag. So the queue is **bounded and lossy**: `publish` returns `False` when full, increments a counter, and returns immediately, and the counter is what an alert watches. Losing a click under load is a strictly better outcome than a slow redirect, and the loss is measurable rather than silent.

**Q9. What stops a malformed code from reaching the cache?**
`RedirectResolver.resolve` validates the format **before** the lookup. A code that fails the length, alphabet or reserved-word check cannot exist in the store, so the check is pure, costs nothing, and — the point — means scanner traffic with junk paths never creates cache keys. Without it, an attacker walking random paths fills the cache with negative entries and evicts the hot codes, which is a cache-poisoning denial of service that looks like a performance problem.

**Q10 (senior). Where does this break at scale?**
Three places, and the first two are the same problem stated twice. The **counter becomes a contended global** — every code allocation touches the same row — which the range allocator in §6 fixes by leasing blocks, at the cost of codes no longer being globally ordered. The **idempotency index becomes a distributed uniqueness constraint**, which is a unique index rather than a lock, because a second process cannot see the first's mutex. And the **cache invalidation on re-point** becomes a cross-node problem: if the code is cached on ten nodes, a re-point must reach all ten, so either the TTL is short enough that staleness is bounded or there is a pub/sub invalidation channel — and with the HLD's read-heavy ratio, a short TTL on mutable links and a long one on immutable ones is the split I would make.

**Q11 (senior). Why not generate the code from the URL deterministically and skip the idempotency index entirely?**
Because determinism is per-URL *only if nothing else changes*, and two things change constantly: the salt, on collision, and the desired length. A pure hash of the URL gives the same code every time, which is exactly the idempotency property — but then a collision has no remedy other than lengthening the code for that one URL, which means the length varies, which means the idempotency lookup must know the length, which means it is no longer a pure function. The index is the honest version: it states the rule explicitly (`url_hash → code`) and lets the generator be anything, including a counter. It also gives a natural place for the ownership and expiry rules, which a pure function of the URL cannot express.

**Q12. What would you test first?**
The three properties that are invisible until they fail in production. The **idempotency race** — twelve threads, one URL, one code — because a duplicate is silent and splits analytics. The **single-flight**, asserted as a load count rather than a timing, because "it felt fast" is not a test. And the **bounded retry**, including a deliberately broken generator that ignores `attempt`, because the failure mode of an unbounded loop is a hung request and the failure mode of a generator that ignores the attempt is a loop that can never succeed. After that, the encoder round-trip and the format validation, which are cheap and catch a lot.

### Pushback round

**P1. "You have three generator strategies but the counter is the recommended one. Why write the other two?"**
Because the choice is the interview. A candidate who writes only the counter has not shown that they know it is injective, and a candidate who writes only the random one has not noticed that collisions can be designed away. Having both makes the trade-off explicit and lets me say which I would ship and why — and the hash generator earns its place because determinism is a genuine property some callers want, at the cost of needing a salt on retry. If the interviewer says "just pick one", I pick the counter and explain the enumerability cost and the permutation fix in one sentence.

**P2. "A thirty-second negative TTL means a freshly created short link can 404 for a client that just created it. That is a bad trade."**
It is a real cost and the demo deliberately exercises the related case by asserting that an *expired* URL can be re-shortened. The mitigation I would actually ship is that the create path writes the positive cache entry directly on insert — which `shorten` does — so the window only exists for a code created through a *different* node than the one serving the first read. That is a narrow window, and the alternative, no negative cache at all, means every scanner request is a database query. If the freshness requirement were strict I would invert it: always write through on create, and drop the negative cache, accepting the scanner cost. It is a trade with a real cost on both sides, and I would rather state the cost than pretend the TTL is free.

**P3. "Your `ObfuscatingGenerator` sketch is not a real cipher, and the `generate` method ignores `attempt` while calling itself with `attempt + 1` — that is confusing and possibly wrong."**
Both criticisms are fair and I flagged the first in the text. The second is a genuine defect in the sketch: applying the permutation to `attempt + 1` rather than to the counter means the class does not compose with the counter at all — it should take a `CounterGenerator` and permute its output, and I wrote it as a standalone that reimplements the counter badly. The correct shape is a decorator: `ObfuscatingGenerator(inner=CounterGenerator(...))`, called as `self.encoder.encode(self._permute(self.encoder.decode(inner.generate(url, attempt))))`. The property to preserve is that a bijection applied to an injective sequence is still injective, which is the whole reason the trick is worth knowing — so the wrapper must be a genuine composition, not a rewrite.

**P4. "Why is `CacheAsideStore._decode` producing a `UrlRecord` with an empty `code` and `url_hash`? That is a half-built object leaking out of the cache."**
Because the cache holds only the fields the redirect needs, and reconstructing a full `UrlRecord` from it is a lie: the `code`, `url_hash` and `created_at` in the returned record are placeholders, and any caller that reads them gets nonsense. That is a genuine design smell and the fix is to cache a distinct type — a small frozen `CachedTarget(long_url, expires_at)` — and return that from the store, so the type system shows that the cache path and the repository path return different things. As written it works for the resolver, which only reads `long_url` and `expires_at`, but it is exactly the kind of placeholder object that becomes a bug the first time somebody adds a field.

## 12. Cheat-sheet summary + cross-links

| Concept | One-line truth |
|---|---|
| The shape | `Base62Encoder` (pure) + `ShortCodeGenerator` (strategy) + `UrlRepository` (two indexes) + `CacheAsideStore` (single-flight) + `RedirectResolver` + `ClickEventPublisher` |
| The generator's contract | `generate(url, attempt)` — a generator that **ignores `attempt`** spins the retry loop forever |
| Why the counter is the default | It is injective: it **cannot collide**, so the retry loop never runs |
| The counter's cost | Sequential and enumerable — fixed by a format-preserving permutation, not by going random |
| Collision retry | **Bounded** (`max_attempts` → `CodeExhausted`), and `insert` **raises** `CodeTaken` |
| Why `insert` raises | A boolean return is a value somebody will not check |
| Idempotency | A second index, `url_hash → code`; the same URL returns the same code |
| The idempotency trap | The lookup and the insert must share a lock — a check-then-insert is a race |
| Normalise before hashing | `/a` and `/a/` must share a code, or the analytics split |
| Custom aliases | **Not** idempotent: a taken alias is an error, not a silent reuse |
| The cache's real job | Not lookup — **single-flight**, so a hot miss costs one load, not a thousand |
| Single-flight detail | `event.set()` in a `finally`, and propagate the leader's error to the waiters |
| Negative cache | Yes, with a **short** TTL — an absent code is looked up repeatedly by scanners |
| Validation order | Format check **before** the lookup, or junk traffic poisons the cache |
| 301 vs 302 | 302 by default: a cached 301 kills analytics **and** re-pointing |
| The policy is per-record | Static assets may be 301; a marketing link never |
| Expiry | Checked **on read**; a reaper is housekeeping, not the authority |
| `410` vs `404` | A lapsed link is not a typo — distinct outcomes |
| Click events | A **bounded, lossy** queue that never blocks a redirect, with a drop counter |
| Drain | Take the batch under the lock, hand it to the sink **outside** it |
| Delete and re-point | Both must **invalidate the cache** |
| Scale-out: the counter | A range allocator — one round trip per block, not per code |

**The three sentences to memorise**

1. *"`generate(url, attempt)` is the contract — a generator that ignores `attempt` returns the same colliding code forever, so the retry loop can never succeed."*
2. *"The counter is the default because it is injective and cannot collide; its cost is enumerable codes, which a format-preserving permutation fixes without reintroducing collisions."*
3. *"The cache's job is single-flight, not lookup — the miss on a hot key is the outage, not the miss on a cold one."*
