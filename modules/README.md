# Modules — Expanded Edition

> **What this folder is:** the topic-by-topic expansion of the 30 survey modules. One folder per module, one Markdown file per teaching topic.
>
> **Version:** 2026.3
> **Contract:** `../MODULE_EXPANSION_SPEC.md`
> **Progress:** `PROGRESS.md` (generated)

---

## 1. How the two layers relate

The root of the repository holds one survey file per module. Those files remain the **module map**: they carry the narrative, the sequence, the labs, and the assessment. They are written to be read in one sitting.

This folder holds the **teaching units**. Each topic file takes one idea from the survey file and expands it until a learner can work with it unaided: mechanics, a worked example with real numbers, runnable code or a calculation, standards context, failure modes, an assumptions ledger, exercises, and answers.

```
00_orientation_and_industry_map.md      <- survey: the whole module in ~540 lines
modules/00_orientation/
  _index.md                             <- map of the expansion
  01_why-this-course-exists.md          <- 1,200-1,800 lines on one topic
  02_the-2026-industry-landscape.md
  ...
```

The survey file is not replaced. A reader who wants the shape reads the survey; a reader who wants to teach or build reads the topic files.

## 2. Folder convention

| Element | Convention | Example |
|---|---|---|
| Module folder | `<id>_<short_slug>` | `06_machine_learning` |
| Module map | `_index.md` | `modules/06_machine_learning/_index.md` |
| Topic file | `NN_<slug>.md` | `08_calibration.md` |
| Assets | `_assets/` | optional figures, CSVs |
| Progress | generated by `tools/scaffold_modules.py` | `modules/PROGRESS.md` |

Ids match the root survey files exactly, including the lettered modules (`01A`, `14A`, `14B`).

## 3. What a topic file contains

Every topic file uses the same 17 sections:

1. Why this topic exists
2. Learning outcomes
3. The core mental model
4. Definitions and vocabulary
5. The mechanics, step by step
6. Worked example
7. Code, query, or calculation
8. Data, standards, and regulatory context
9. Industry practice and case evidence
10. Failure modes and red flags
11. Assumptions and limits
12. Exercises
13. Self-check answers
14. Interview questions
15. Key terms
16. Sources
17. Links

The fixed skeleton means a learner always knows where to find the worked example, and an instructor always knows where to find the exercises. It also makes the package auditable: a missing section is visible.

## 6. Status vocabulary

| Status | Meaning |
|---|---|
| `planned` | Listed, not written |
| `draft` | Written, below 1,000 lines or missing sections |
| `complete` | Meets the quality bar |
| `reviewed` | Read by a second person |
| `revised` | Reviewed and corrected |

Only `complete` and above count toward a module's line total. The current counts are always in `PROGRESS.md`.

## 7. Regenerating the scaffold

```bash
python tools/scaffold_modules.py
```

This rewrites every `_index.md` and `PROGRESS.md` from the manifest. It never deletes topic files. Run it after adding topics to the manifest.

## 8. Boundary

Expansion adds **depth**, not **validation**. The course remains unvalidated, unaccredited, and not regulatory approved. Regulatory content is educational, not legal or medical advice. Source claims are desk-checked with documented exceptions. See `../VALIDATION_STATUS.md`.
