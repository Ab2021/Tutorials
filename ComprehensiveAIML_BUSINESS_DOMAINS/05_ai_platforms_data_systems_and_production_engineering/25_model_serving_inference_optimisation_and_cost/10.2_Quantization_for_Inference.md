# 10.2 — Quantization for Inference

> **Course location:** Module 25. This lesson maps to `finetuning_course/Module_10_Inference_Deployment/10.2_Quantization_for_Inference.md` in [`Train/Templates/directory.txt`](../../../Templates/directory.txt). The source body was unavailable; this is a new mapped draft.
>
> **Boundary:** A bit-width estimate is not a memory, latency or quality result. Quantization format, scales/zero points, grouping, outliers, compute dtype, kernel and workload all matter.

## Learning outcomes

Learners can distinguish storage, compute and activation/KV precision; calculate raw dense weight payload; require calibration and slice-quality evidence; and decide whether a quantized artifact meets accuracy, safety and operational gates.

## 1. Storage accounting

For `P` stored weight elements at `q` bits/element, raw packed payload is `P*q/8` bytes before metadata/alignment. A 7-billion-element checkpoint at 16 bits has raw payload `7e9*2=14e9` bytes; at 4 bits it has `7e9*.5=3.5e9` bytes. The ratio is 4x for the raw weight codes only.

Scales, zero-points, group metadata, outlier paths, packing/alignment, duplicated buffers, dequantization workspace, activations, KV cache and allocator overhead are additional. A model whose raw codes fit can still OOM or be slower if its kernel/workspace path is unsuitable.

## 2. Compatibility contract

Pin the base checkpoint, tokenizer, model architecture, quantizer/version/configuration, group size, calibration method/data provenance, codebook/scales, compute/accumulation dtype, target kernel/runtime/driver and output artifact hash. Quantizing a different revision and keeping a familiar model name is not reproducible.

Calibrate/evaluate on representative input lengths, languages/domains, safety cases and tool/schema outputs. Quantization error can concentrate in rare tokens, long contexts, outlier layers or critical slices; pooled average quality can conceal it.

## 3. Validation protocol

1. Run baseline and candidate with identical prompts, context policy, decoding, tools and scoring.
2. Compare task/safety/slice outcomes and valid-output rate; retain paired errors and outputs.
3. Measure warm/cold latency, TTFT, ITL, throughput and peak memory on target hardware under declared load.
4. Verify artifact load, deterministic metadata, rollback pointer and monitoring labels.
5. Promote only if predeclared non-inferiority/critical gates and operational constraints pass.

A lower bit-width candidate that passes generic perplexity but breaks JSON validity or a critical safety refusal fails the deployment contract.

## 4. Failure modes

| Symptom | Check | Response |
|---|---|---|
| Weight payload shrinks but peak memory does not | Allocation timeline for workspace/KV/activations/duplicates | Diagnose live categories; do not claim memory win from code bits |
| Quantized run is slower | Target kernel support, dequantization path, batch/context mix | Use supported runtime or retain higher precision |
| Long-context regression | Length/position slices and KV/precision policy | Gate by context slice; revise method/policy |
| Rare-token/output-format errors | Domain/language/schema slices and raw outputs | Add slice gate; recalibrate or reject candidate |
| Artifact mismatch after reload | Config/scale/checksum and fixed-output comparison | Rebuild from pinned inputs; version artifact separately |

## 5. Bounded decision

A 4-bit candidate gives a 4x raw weight-code reduction relative to 16-bit storage. **Decision:** treat this only as a storage hypothesis. Measure target runtime peak, latency and full quality suite; include metadata/workspace/KV. Release only if every critical slice and SLO pass with an immutable rollback artifact.

## 6. Interview checks

1. **Does 4-bit mean four times lower device peak?** No; raw weights are one allocation category.
2. **Why pin compute dtype?** Stored code precision and arithmetic precision can differ.
3. **What validates a candidate?** Paired quality/safety slices plus target-runtime capacity/latency.
4. **Why can one format be slower?** Unsupported/dequantization-heavy kernels or workload mismatch.
5. **What is the safe default after critical regression?** Reject or roll back; do not average it away.

## 7. Quick reference

| Claim | Required evidence |
|---|---|
| Smaller | Raw-code arithmetic plus serialized/runtime allocation evidence |
| Faster | Target kernel/hardware and workload percentile measurements |
| Equivalent quality | Paired task/safety/slice/format evaluation under matched policy |
| Deployable | Immutable lineage, monitoring and rollback |
