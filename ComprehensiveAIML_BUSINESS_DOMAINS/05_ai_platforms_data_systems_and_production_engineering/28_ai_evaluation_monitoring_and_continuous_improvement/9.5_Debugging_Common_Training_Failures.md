# 9.5 — Debugging Common Training Failures

> **Course location:** Module 28. This lesson maps to `finetuning_course/Module_09_Evaluation_Debugging/9.5_Debugging_Common_Training_Failures.md` in [`Train/Templates/directory.txt`](../../../Templates/directory.txt). The source body was unavailable; this is a new mapped draft.
>
> **Rule:** A symptom is not a cause. Preserve the first failing batch, event timeline, immutable artifacts and environment evidence before changing hyperparameters.

## Learning outcomes

Learners can contain a failed run, identify its earliest observable divergence, separate data/objective/precision/optimizer/distributed/system hypotheses, execute a minimal discriminating check, and restore only from a traceable good checkpoint.

## 1. Triage sequence

1. **Contain:** stop promotion; prevent corrupt checkpoint reuse; preserve logs, config, manifests, batch IDs, seeds and environment IDs.
2. **Locate:** find first nonfinite value, metric discontinuity, data/config event or throughput collapse—not the last visible error.
3. **Classify:** data/labels; objective/mask; optimizer/precision; distributed synchronization; runtime/hardware; evaluation/logging.
4. **Minimize:** reproduce on one deterministic batch or tiny fixed shard with the same checkpoint and configuration.
5. **Discriminate:** change one causal axis, inspect the affected tensor/contract, then rerun the minimal case.
6. **Recover:** resume only from a verified checkpoint with dataset/config/optimizer compatibility; run held-out regression before promotion.

Never “fix” a NaN by silently replacing it with zero, dropping arbitrary batches, changing both learning rate and data, or selecting the most favorable retry.

## 2. Evidence map

| Symptom | Plausible causes | First discriminating check | Bounded response |
|---|---|---|---|
| Loss is NaN/Inf | Invalid IDs, empty denominator, overflow, nonfinite activations, kernel/hardware fault | First nonfinite tensor and batch; labels/mask; scaler/precision events | Stop; isolate batch/tensor; correct root cause before resuming |
| Loss is zero/very low immediately | All targets masked, label copied from input, leakage, resumed state mismatch | Decode input/labels/mask; provenance/duplicate audit | Fix objective/data; invalidate misleading checkpoints |
| OOM at load | Wrong precision, duplicate weights, process contention, allocator fragmentation | Process/device inventory and allocation timeline | Remove unintended allocations; confirm footprint model |
| OOM at first step | Optimizer states, gradients, activations, sequence/batch change | Timeline by allocation category and token lengths | Adjust one validated capacity control; retest fixed batch |
| Rank-to-rank hang | Uneven batches, collective mismatch, exception on one rank, network fault | Per-rank progress/stack traces and collective sequence | Abort coherently; align data/control flow before retry |
| Loss spike after resume | Scheduler/optimizer state absent, data order/config/template changed | Compare checkpoint metadata and first resumed batches | Resume only compatible state or declare a new run |
| Throughput collapse | Data/I/O stall, checkpointing, sequence length shift, compilation/recompile | Wait time, I/O, length, kernel and checkpoint events | Isolate subsystem; do not infer quality regression |
| Held-out metric improves implausibly | Leakage, changed evaluator/mask/template, selected retries | Frozen manifest, item overlap, version diff | Quarantine result and recompute matched evaluation |
| Gradient clipping always fires | LR/scale/data outliers, reduction change, bad initialization | Unclipped norm, clip fraction, batch/slice and LR | Identify event; change one axis and validate behavior |

## 3. Invariants to check before tuning

- Every target ID is in vocabulary range; each scored batch has a positive target denominator.
- Rendered template, target shift, masks, special-token policy and truncation match the declared objective.
- Dataset manifest, split/dependency boundary and duplicate controls match the run record.
- Trainable parameters, optimizer groups and scheduler state match the intended checkpoint.
- Distributed ranks execute compatible collectives with deterministic failure propagation.
- Checkpoint includes or intentionally excludes optimizer/RNG/scheduler/data-position state; the resume policy names this.
- Evaluation uses a frozen candidate ID, manifest, decoding/template and scorer.

## 4. Minimal numerical diagnostic

If a batch has 128 positions but only `m=0` eligible labels, masked mean loss is undefined because its denominator is zero. Recording `0` falsely implies perfect prediction. If `m=32`, log both NLL sum and `32`; a changed denominator can explain a changed displayed loss without a model improvement.

For gradient accumulation, an “effective batch” claim requires matching loss scaling and update timing. Four microbatches of eight examples are not automatically equivalent to one batch of 32 when dropout, sequence lengths, distributed reduction, clipping or scheduler stepping differs. Verify completed optimizer updates and target-token counts, not the label alone.

## 5. Bounded incident exercise

At update 18,400, loss becomes NaN after a data pipeline deployment. **Decision:** halt the run; capture the first nonfinite batch and compare pre/post rendered samples, IDs, labels, masks, lengths and denominator. Then replay the batch in a fixed environment and inspect logits, loss terms, gradients and scaler state. If invalid labels/masks caused the issue, correct the pipeline, invalidate affected checkpoints and resume only from a pre-change checkpoint after a held-out regression. Do not lower learning rate first: timing implicates the pipeline but does not prove it.

## 6. Interview checks

1. **First response to NaN?** Contain, preserve the first failing evidence and locate the first nonfinite tensor.
2. **Why not drop the bad batch?** It can hide a systematic contract defect and bias data.
3. **Why decode labels/masks?** A loss curve can look healthy while supervising the wrong tokens.
4. **What makes a resume valid?** Compatible model/data/config/optimizer/scheduler/RNG policy and explicit evidence.
5. **What proves a distributed hang cause?** Per-rank traces and collective/control-flow evidence, not timeout alone.
6. **When can a checkpoint promote after repair?** After matched held-out task/guardrail regression and lineage checks.

## 7. Quick reference

| Stage | Required artifact |
|---|---|
| Contain | Immutable logs, config, manifests, checkpoint and environment IDs |
| Locate | First divergent step/batch/tensor/event |
| Diagnose | One discriminating check per hypothesis |
| Recover | Verified compatible checkpoint and fixed-contract smoke run |
| Promote | Frozen held-out regression, not restored train loss alone |
