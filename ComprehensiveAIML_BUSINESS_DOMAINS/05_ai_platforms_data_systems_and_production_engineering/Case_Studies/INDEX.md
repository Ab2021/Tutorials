## Purpose

This collection will hold cross-module cases for **AI Platforms, Data Systems and Production Engineering**. Unlike module-specific cases, each case should require at least two modules from this part and show business context, constraints, architecture, metrics, trade-offs, failure modes, and evidence.

## Planned case-study formats

1. **Design case:** ambiguous requirements to a justified architecture.
2. **Implementation case:** data/model/platform choices with validation steps.
3. **Incident case:** symptom, blast radius, diagnosis, remediation, and prevention.
4. **Decision case:** compare alternatives using cost, risk, quality, latency, and adoption criteria.

## Candidate threads

- GPU Architecture, Accelerators and AI Hardware: Size an inference cluster; profile memory-bound training
- Distributed Training, Data Pipelines and ML Compute: Train a large model on limited cluster capacity; recover from checkpoint failures
- Model Serving, Inference Optimisation and Cost: Multi-model inference gateway; reduce p99 LLM latency
- MLOps, Feature Platforms and Model Lifecycle: Deploy a credit model safely; feature freshness incident response
- Data Quality, Observability and Reliability Engineering: Broken upstream schema incident; silent label corruption investigation
- AI Evaluation, Monitoring and Continuous Improvement: RAG quality regression; agent tool-use failure analysis
