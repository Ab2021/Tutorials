## Learning outcomes

Given multiple responses sampled for the same prompt, learners can derive group-relative reward normalization; state its population-standard-deviation and zero-variance conventions; distinguish group-relative advantages from a learned value baseline; explain the policy-ratio objective and token masks; identify reward/verifier leakage and group-composition risks; and design held-out evaluation for a verifiable task.

## 1. Why group-relative comparisons

Group Relative Policy Optimization (GRPO) uses multiple candidate completions for a prompt and constructs relative learning signals from their rewards. A common formulation standardizes rewards within each prompt's sampled group and uses the resulting advantage-like values in a policy-gradient objective. This can avoid a separate learned value critic in that formulation, but it does not remove the need for valid reward signals, rollout sampling, policy updates, baseline controls or careful evaluation.

The “relative” baseline asks which sampled outputs did better than their peers under the configured scorer. It does not establish that any sample is correct in absolute terms. If every candidate is wrong, a group still has a relative winner; if all scores tie, within-group standardization has no variance and requires an explicit policy.

Keep separate:

- **Policy `pi_theta`:** generates candidates and is updated.
- **Old/behavior policy:** generated the rollouts whose token probabilities define an update ratio.
- **Reference policy, when used:** anchors an explicit KL/divergence penalty; not the same logical role as the group mean.
- **Reward/verifier:** assigns scalar scores from outcome checks, preference models, rules or a combination.
- **Group:** candidates associated with the same prompt and reward context; its membership determines each relative signal.

## 2. Group reward standardization

For one prompt, let `r_i` be the reward for sampled completion `i` in a group of size `G`. A common group-relative advantage is the centered reward divided by the group's population standard deviation:

```text
FORMULA [GRPO-01]: mu = (1/G) * sum_i r_i
                  sigma = sqrt( (1/G) * sum_i (r_i-mu)^2 )
                  A_i = (r_i-mu) / sigma
WHERE: r_i is reward [declared reward units]; G is group size [completions/prompt];
       mu is group mean; sigma is population standard deviation; A_i is a
       dimensionless standardized relative score.
CONSTRAINT: G>0; the example convention uses population divisor G (not G-1);
            define sigma=0 behavior explicitly. Implementations may add epsilon,
            omit standard-deviation scaling, or use another normalization.
NUMERICAL EXAMPLE: rewards [0,1,1,2]; mu=1; variance=0.5; sigma=sqrt(0.5);
                   A≈[-1.4142,0,0,1.4142].
INTERPRETATION: the high-reward completion is one population-standard-deviation
                above this group's mean; values depend on group composition.
```

With a zero-variance group, `r_i=mu` for all members, so the unregularized formula divides by zero. A safe explicit convention is to set every group advantage to zero and skip the policy-gradient contribution for that group (or use an implementation's documented epsilon policy with a justified effect). Adding epsilon to the denominator alone gives zeros for exactly tied scores, but near-zero variance can create large normalized values; clip/scale behavior and thresholds must be tested. Never divide by zero or silently discard such groups without logging counts and consequences.

Alternative conventions include centered rewards without variance scaling, standard deviation with a numerical floor, or reward ranking. These are different objectives/gradient scales. Record group size, sampling policy, reward aggregation, standard-deviation divisor, epsilon/floor, zero-variance treatment, and any clipping/normalization after standardization.

## 3. Worked group example

ILLUSTRATIVE scores for four responses to one prompt are `[0,1,1,2]`.

1. Mean: `(0+1+1+2)/4=1`.
2. Deviations: `[-1,0,0,1]`.
3. Squared deviations: `[1,0,0,1]`; mean square=`2/4=0.5`.
4. Population standard deviation: `sqrt(0.5)≈0.7071068`.
5. Standardized values: `[-1/0.7071,0,0,1/0.7071]≈[-1.4142,0,0,1.4142]`.

**Independent checks:** advantages sum to zero; mean square of the standardized values is `(2+0+0+2)/4=1`; using sample standard deviation would use divisor 3 and produce different magnitudes, so state the convention. If rewards were `[1,1,1,1]`, then sigma=0 and the specified zero-variance rule returns `[0,0,0,0]`. These checks validate normalization arithmetic, not reward quality or learning.

Group-relative signals create dependence: each response's advantage depends on the other sampled completions. Increasing group size changes the mean/scale estimate and the chance of sampling a high-quality completion, but also increases generation cost. Comparisons across different prompts are not automatically calibrated because each group is centered and scaled separately.

## 4. Policy objective and sampled-token ratios

A GRPO policy update commonly uses a clipped probability-ratio surrogate, with group advantage attached to actions/tokens in the response. A simplified token-level expression resembles PPO's clipped objective:

```text
FORMULA [GRPO-02]: rho_(i,t) = pi_theta(a_(i,t)|s_(i,t)) /
                                pi_old(a_(i,t)|s_(i,t))
                  L = E_(i,t)[ min(rho_(i,t)*A_i,
                         clip(rho_(i,t),1-epsilon,1+epsilon)*A_i) ]
WHERE: i indexes a sampled completion; t indexes response action/token;
       A_i is its group-relative score; rho is dimensionless; epsilon>0.
CONSTRAINT: maximize L (or minimize its negative); use the actual response mask,
            rollout log probabilities and documented token/example denominator.
            Some variants use token-level advantages or other weighting.
NUMERICAL EXAMPLE: rho=1.25, epsilon=0.2, A_i=1.4142 gives
                   min(1.25*1.4142,1.2*1.4142)≈1.6971.
INTERPRETATION: the positive sample's surrogate contribution uses the clipped
                ratio in this case; it is not a hard bound on all policy changes.
```

The expression is a simplified teaching form, not a claim that every GRPO implementation uses identical ratios, clipping or reduction. Some objectives add KL terms, use per-token importance ratios, normalize by response lengths, combine multiple reward channels, or apply additional clipping. Confirm the chosen algorithm's exact equation and signs. Log whether a metric is maximization objective or negative loss.

The main conceptual difference from a common actor-critic PPO setup is the construction of relative advantages from groups rather than estimating a separate value baseline. This does not make GRPO “critic-free” in every variant or eliminate value-like baselines in all implementations. Name the actual implementation and its model components.

## 5. Reward design and verifiers

A reward can be rule-based correctness, format validity, preference score, safety score, process label, or a weighted composition. A verifiable task may support exact execution or a deterministic answer checker, but even a verifier can have defects: weak tests, accepted alternative formats, hidden leakage, reward for verbosity, or non-independent test labels.

For each reward component, document:

- which behavior it measures and its unit/range;
- whether reward is per-token, per-step, per-response or grouped;
- score source, rubric/version, model/verifier version and calibration limits;
- weighting between components and conflict resolution;
- treatment of invalid, timeout, refusal, partial and malformed responses;
- susceptibility to gaming, leakage, answer memorization and length bias;
- independent human/task outcome against which it will be checked.

Do not give a high reward for proxy properties that can be achieved without the task objective. For code/math, tests should include hidden or held-out cases and evaluate actual correctness, not matching a visible answer string alone. For safety/grounding, reward-model scores require expert review and independent challenge sets.

## 6. Group sampling, compute and data boundaries

For each prompt, sample `G` completions with controlled decoding. The group should share the same prompt, retrieved evidence and policy contract if reward differences are intended to compare response quality. If context or tool outputs differ, the group is not a clean within-prompt comparison unless the design explicitly accounts for those differences.

Record prompt IDs, group membership, response token counts, stop/truncation, sampled policy/version, random seeds, rewards, reward components, verifier failures, masks and log probabilities. Avoid placing variants from the same prompt/source into independent train/test splits as if they were unrelated. Hold out problem families, source documents or time where the deployment claim requires generalization.

Generation cost scales with candidates per prompt and response length. A larger group can improve the chance of seeing a high-reward sample, while increasing tokens, latency and memory. Estimate cost from actual prompt and completion tokens, not merely number of prompts. Report cost per usable/verified sample and per completed update; invalid/duplicate samples still consume resources.

## 7. Evaluation and ablation

Evaluate a GRPO policy against a comparable SFT baseline and, where decision-relevant, DPO/PPO alternatives. Hold fixed prompts, system instructions, tools/retrieval, decoding protocol, task budget and evaluation rubric. Report:

- objective/task success and uncertainty by prompt family and difficulty;
- reward components and independent human/external verifier agreement;
- invalid-format, timeout, refusal and unsafe-action rates;
- general-capability and safety regressions;
- response length, token-normalized cost and latency;
- group size, reward variance, zero-variance/invalid group fraction;
- policy/reference divergence, ratio/clipping statistics and update stability;
- train, validation and untouched test data provenance and contamination checks.

Ablate reward components, group size or normalization one at a time when feasible. If reward scales differ substantially, test whether a component dominates gradients. Report seed variability and prompt-level uncertainty. Do not select a policy solely by mean reward computed on the same scorer used for training.

## 8. Failure diagnostics

| Symptom | Candidate causes | Discriminating check | Bounded response |
|---|---|---|---|
| All group advantages become NaN | Zero standard deviation, non-finite reward, empty/invalid group | Log raw rewards, group count, finite flags, sigma and denominator | Apply the declared zero-variance/invalid-group policy; fail fast on nonfinite scores |
| Near-tie groups create extreme updates | Tiny sigma, no floor/clipping, noisy reward precision | Histogram sigma and advantage magnitude; recompute in stable precision | Use a justified floor or normalization policy and retest gradient scale; log affected groups |
| Reward improves but verifier/human quality falls | Reward hacking, verifier leakage, training distribution shift | Independent hidden tests/human review on high-reward examples | Stop/revert; repair reward/verification and holdout separation before further updates |
| Policy optimizes lucky samples, not robust behavior | Small group, high reward variance, prompt sampling bias | Repeat groups per prompt; assess within-prompt success probability and held-out families | Increase evidence or revise sampling; report generation cost and uncertainty |
| Scores cannot compare prompts | Per-group centering/normalization removes between-group scale | Compare raw reward distributions and external outcomes across prompt classes | Use group-relative advantages only for within-prompt update; separately evaluate absolute success |
| Longer answers gain reward | Length-sensitive reward/verifier or token-summed objective | Regress reward/quality on length; compare matched-length outputs and cost | Clarify rubric/reward and length policy; verify quality without hiding valid detail |
| Many zero-reward groups | Verifier rejects all; task too hard; formatting/API error | Inspect completions, verifier traces and one known-correct control | Fix verifier or task/data; avoid interpreting a no-signal group as negative preference evidence |
| Success collapses on hidden variants | Verifier/answer leakage or narrow task-family training | Split by source/family/time; test novel compositions and adversarial variants | Repair leakage and retrain/evaluate on independent cases |
| Learning differs across batches with same reward mean | Different group composition, variance normalization or masks | Compare full group reward distribution, sigma and token denominators | Preserve group definitions and global reduction; include distribution in run logs |
| Training is costly without useful gain | Too many samples, long completions, weak task signal, overlarge group | Measure tokens per verified success and time-to-quality by group size | Reduce scope/group cost only if independently validated; retain baseline otherwise |

## 9. Decision: grouped optimization or DPO/PPO?

A group-relative policy experiment is most defensible when multiple completions can be sampled for the same prompt, meaningful reward differences can be assigned, and candidate quality is testable independently. DPO may fit fixed preference-pair data; PPO may be appropriate for a learned reward and policy optimization where its critic/KL machinery is justified; SFT may suffice when correct demonstrations directly express the desired behavior.

Choose using the smallest controlled experiment that can answer the decision. For one verifiable task, compare a baseline with a grouped policy only if the group reward is independent enough to distinguish correct from incorrect outcomes. Hold out problem families, audit the verifier, cap compute and predeclare safety/quality gates. No algorithm is preferred solely because its name suggests fewer model components.

## 10. Interview and self-check questions

### Q1. Why sample a group of completions for one prompt?
**Answer:** To estimate relative reward differences among candidates conditioned on a shared prompt.
**Reasoning:** Group mean/scale creates a within-prompt advantage signal.
**Follow-up:** Does the group winner have to be correct?
**Answer:** No; all samples may be wrong or the verifier may be defective.

### Q2. Normalize rewards `[0,1,1,2]` with population standard deviation.
**Answer:** Mean 1, standard deviation `sqrt(0.5)≈0.7071`, advantages approximately `[-1.4142,0,0,1.4142]`.
**Reasoning:** Deviations are `[-1,0,0,1]`, population variance is `2/4`.
**Follow-up:** What is the sample standard deviation?
**Answer:** `sqrt(2/3)≈0.8165`; it gives different normalized magnitudes.

### Q3. What is the zero-variance case?
**Answer:** All group rewards are equal, so sigma is zero and unregularized normalization is undefined.
**Reasoning:** Division by zero.
**Follow-up:** Give an explicit safe convention.
**Answer:** Set advantages to zero and skip that group's policy-gradient contribution, while logging it.

### Q4. How does group-relative advantage differ from a learned value baseline?
**Answer:** It centers/scales sampled rewards within a prompt's group rather than estimating expected return with a separate value network in the common formulation.
**Reasoning:** The baseline source and its dependence structure differ.
**Follow-up:** Does that mean every GRPO variant has no critic-like component?
**Answer:** No; implementations vary.

### Q5. What does per-group normalization do to cross-prompt score meaning?
**Answer:** It removes or rescales between-group differences; normalized values express relative standing within each group.
**Reasoning:** Each prompt receives its own mean and scale.
**Follow-up:** How evaluate absolute task performance?
**Answer:** Use independent task success rates and calibrated external metrics.

### Q6. What does clipping do in the simplified policy objective?
**Answer:** Limits the surrogate contribution for certain ratio/advantage combinations.
**Reasoning:** It compares unclipped and clipped terms via a sign-sensitive minimum.
**Follow-up:** Does it guarantee a global probability or KL bound?
**Answer:** No.

### Q7. Name two verifier-leakage risks.
**Answer:** Training on visible expected answers and splitting near-identical problems across train/test.
**Reasoning:** Policy may exploit artifacts or memorize test content.
**Follow-up:** How mitigate?
**Answer:** Hidden tests and family/source/time-separated held-out evaluation.

### Q8. Why can larger groups increase compute cost?
**Answer:** More generated completions and response tokens must be sampled, scored and processed per prompt.
**Reasoning:** Prompt count alone understates token work.
**Follow-up:** What metric is useful?
**Answer:** Token cost or wall-clock per independently verified success.

### Q9. What if verifier reward rises but hidden-task correctness declines?
**Answer:** Stop or revert the policy and investigate reward mismatch/leakage.
**Reasoning:** The training reward is a proxy, not the objective.
**Follow-up:** What evidence should promotion use?
**Answer:** Independent verifier/human/task results and safety/regression gates.

### Q10. When might DPO be simpler?
**Answer:** When fixed, reliable preference pairs exist and online grouped sampling is not needed.
**Reasoning:** DPO directly trains on pairs without generating multiple rollouts per prompt during the basic objective.
**Follow-up:** Is DPO automatically better?
**Answer:** No; compare data assumptions, cost and held-out outcomes.
