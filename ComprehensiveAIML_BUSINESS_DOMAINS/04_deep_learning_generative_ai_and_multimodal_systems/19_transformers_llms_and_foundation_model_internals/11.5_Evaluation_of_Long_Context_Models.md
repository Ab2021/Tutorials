# 11.5 — Evaluation of Long-Context Models

> **Course location:** Module 19. This lesson maps to `finetuning_course/Module_11_Context_Length_Extension/11.5_Evaluation_of_Long_Context_Models.md` in [`Train/Templates/directory.txt`](../../../Templates/directory.txt). Source body unavailable; new mapped draft.

## Learning outcomes

Learners can define position-aware long-context evaluation, distinguish window fit from evidence use, compare extension with retrieval under matched budgets, and gate deployment by quality, grounding, cost and tail behavior.

## 1. Test the claimed behavior

A valid suite varies length, evidence position, distractor/conflict density, multi-document provenance, answer type and language/domain. Include short-context controls, evidence at beginning/middle/end, no-answer/unsupported cases, conflicting evidence, noise, and target-length requests. Freeze position IDs, truncation, prompt/template, retrieval settings, decoding and scorer.

Report coverage by length/position slice and preserve raw outputs/evidence traces subject to policy. A model can answer a near-start needle while failing middle evidence or hallucinating support; aggregate accuracy is not a complete claim.

## 2. Compare alternatives fairly

Compare the extension candidate with a retrieval/chunking baseline under the same source documents, answer rubric, context/output budget, latency/cost limit and safety/grounding gates. Retrieval has recall/ranking risks; extension has context/cost/position risks. Select the smaller validated system that meets the task contract.

## 3. Core gates

| Gate | Evidence |
|---|---|
| Evidence use | Correct answer plus cited/supported source at each position slice |
| Robustness | Distractor/conflict/no-answer behavior and error taxonomy |
| Regression | Matched short-context/general task suite |
| Operations | Target-length TTFT/ITL, peak memory, error/rejection and cost |
| Validity | Dependency-separated provenance, contamination review and scorer audit |

## 4. Failure modes

| Symptom | Check | Response |
|---|---|---|
| Higher window but no middle gain | Position sweep | Do not claim usable extension; revise policy or choose retrieval |
| Good needles, poor real documents | Naturalistic multi-document/task set | Rebalance suite and limit claim |
| Longer context increases hallucination | Supported/unsupported evidence audit | Add grounding gate; reduce/select evidence |
| Candidate wins quality but misses SLO | Matched load/cost/tail measurement | Reject or constrain route |

## 5. Bounded decision

Promote a long-context candidate only if it passes predeclared position/length evidence gates, short-context non-inferiority, grounding/safety, target-runtime cost/latency and provenance/scorer validity. Otherwise retain retrieval/chunking or restrict scope.

## 6. Quick reference

| Claim | Required evidence |
|---|---|
| Uses long context | Position/length/distractor task evaluation |
| Better than retrieval | Matched quality, grounding, cost and tails |
| Ready | Valid suite, gates, artifact lineage and rollback |
