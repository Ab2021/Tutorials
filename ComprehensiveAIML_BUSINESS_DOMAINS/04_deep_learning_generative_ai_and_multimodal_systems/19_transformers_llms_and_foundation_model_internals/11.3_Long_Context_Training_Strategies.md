# 11.3 — Long Context Training Strategies

> **Course location:** Module 19. This lesson maps to `finetuning_course/Module_11_Context_Length_Extension/11.3_Long_Context_Training_Strategies.md` in [`Train/Templates/directory.txt`](../../../Templates/directory.txt). Source body unavailable; new mapped draft.

## Learning outcomes

Learners can select a position/length curriculum, preserve short-context capability, construct long-document data controls, and gate extension with position, noise, cost and regression evaluation.

## 1. Strategy choices

Long-context adaptation combines an architecture-compatible positional policy with training examples that require distant evidence. Options include continued training/fine-tuning at longer sequences, staged length curricula, position interpolation or architecture-specific scaling, and retrieval/chunking instead of extension. No option proves reliable use of distant information without evaluation.

A curriculum can increase length gradually to control memory and optimization behavior, but it changes the data/position distribution at each stage. Record length mixture, token exposure, truncation, packing boundaries, position IDs, optimizer/schedule state and checkpoint lineage. Do not compare a final long-context run to a short-context baseline when data, tokens, model revision and evaluation protocol all changed.

## 2. Data contract

Use licensed long documents with dependency-aware splits. Preserve document boundaries, source/provenance, distractors, answer evidence locations, multilingual/domain balance and near-duplicate controls. Synthetic long examples can target position behavior but can also teach artifacts; retain generator/prompt/version and separate generator-contaminated evaluation.

For an original window `L_old=4096`, target `L_new=16384`, and original position `p_old=12000`, a simple position interpolation convention gives `p_new=p_old*L_old/L_new=3000`. This arithmetic describes one stated convention, not a universal checkpoint conversion or quality result.

## 3. Evaluation gates

Evaluate short, trained-length and target-length inputs; beginning/middle/end evidence; conflict and distractor cases; answer citation/grounding; cost, memory and latency; and degradation of original capabilities. Freeze position policy and context/truncation settings. Compare retrieval/chunking control under the same task and budget.

## 4. Failure modes

| Symptom | Check | Response |
|---|---|---|
| Long window fits but misses evidence | Position/distractor sweep | Revise training/policy or use retrieval; do not claim reliability |
| Short tasks regress | Matched short-context suite | Keep short examples/gate or reject extension |
| OOM at target length | Token/batch/KV/workspace peak | Change supported capacity policy and retest |
| Artificial benchmark gain | Source/duplicate/generator audit | Quarantine contaminated items and rebuild holdout |

## 5. Bounded decision

Choose a staged long-context run only if a retrieval baseline cannot meet the required evidence-position task within budget. Promote only when target-length, short-context, grounding and operational gates pass on dependency-separated data.

## 6. Quick reference

| Claim | Required evidence |
|---|---|
| Training extends usable context | Position/length/noise task results, not fit alone |
| Position conversion is valid | Architecture/checkpoint-specific policy and regression tests |
| Ready to deploy | Short/long quality, memory/latency and rollback gates |
