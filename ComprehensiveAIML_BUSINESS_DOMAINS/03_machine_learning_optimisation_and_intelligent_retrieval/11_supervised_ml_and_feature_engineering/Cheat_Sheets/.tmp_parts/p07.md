
## 7. Comparison / Selection Table

### 7.1 The primary selection table

Read this table by constraint first, then by score. The constraint columns are the ones that eliminate candidates; only among survivors does accuracy matter.

| Criterion | Ridge / logistic | Lasso / elastic net | Single tree | Random forest | Boosted trees | Linear-leaf tree |
|---|---|---|---|---|---|---|
| Extrapolates beyond observed range | Yes, along the slope | Yes, for retained features | No | No | No | Partly, inside each leaf's slope |
| Captures high-order interactions without explicit features | No | No | Yes, at cost in depth | Yes | Yes, most efficiently | Yes plus within-leaf trend |
| Coefficient-level explanation | Direct, per unit of the feature | Sparse set, per unit | None | None | None | Per leaf, conditional |
| Stable under correlated features | Yes, sign-stable | No, selection flips | Not applicable | Yes by averaging | Yes by sampling | Depends on leaf size |
| Handles `p > n` | With penalty | With penalty | Yes, by construction | Yes | Yes | Yes |
| Monotone constraint support | Trivial sign restriction | Trivial sign restriction | Possible but crude | Awkward | Native, per feature | Native plus slope |
| Training cost on 200k × 60 | Seconds | Seconds to a minute | Under a second | Minutes | 1–10 minutes | Minutes, more if refitting leaves |
| Model size | `p + 1` numbers | Non-zeros only | Nodes of one tree | `B` trees | `M × J` leaves | `M × J` leaves plus slopes |
| Typical failure | Missed interactions | Unstable selection | Variance | Cannot extrapolate | Overfits small leaves | Coefficient noise in thin leaves |
| Default first choice when | Target is smooth and additive | Many features, few useful | A rule must be readable | Variance dominates | Tabular accuracy matters | Global trend plus local structure |

### 7.2 Selection by decision requirement

The table above compares models. This one starts from what the decision needs, which is how a practitioner should actually enter the problem.

| Requirement | Choose | Reject | Reason |
|---|---|---|---|
| A regulator asks why one record scored as it did | Logistic regression, or a depth-2 boosted model with few trees | A 500-tree depth-8 ensemble | The explanation must be stable enough to defend in writing |
| A monotone relationship is contractual | Monotone-constrained boosting or a signed linear model | An unconstrained forest | An unconstrained model can violate the contract on a single feature |
| The scoring latency budget is 1 ms per row | Linear model, or a small tree ensemble | A 1,000-tree ensemble | Section 9 computes the traversal cost |
| The population shifted and the top feature's scale changed | Linear model with standardised inputs | A tree, which is invariant but gives no signal | Trees hide scale shift; linear models expose it as a coefficient move |
| There is one strong linear driver plus a few interactions | Boosted trees with shallow depth, or linear-leaf trees | A deep forest | Depth spends capacity rebuilding the linear trend |
| Rows arrive in a stream and the model retrains nightly | Linear model or a very shallow ensemble | A deep ensemble | Retraining cost dominates operational cost |
| The label is heavily delayed and only 2% positive | Any family, but with the calibration protocol from sheet 05 | Default thresholds from a tutorial | The threshold, not the family, drives the error |

### 7.3 Choosing capacity control, not just family

Once a family is chosen, the knobs are not interchangeable and the order matters.

| Situation | First knob | Second knob | Do not touch yet |
|---|---|---|---|
| Validation curve still falling at the last round | Rounds | Shrinkage | Depth |
| Validation loss minimum is at round 20 of 1,000 | Rounds, with early stopping on a third split | Shrinkage | Lambda |
| Deepest leaves hold 3–5 rows | `min_child_weight`, then depth | Lambda | Rounds |
| Feature importances concentrated on one identifier column | Column subsampling | Permutation importance audit | Lambda |
| Model must be monotone in one feature | Monotone constraint | Depth reduction on that subtree | Shrinkage |
| Predictions flat beyond the training range and that is unacceptable | Family change or a linear term | Linear leaves | Rounds |

### 7.4 What each family costs you in explanation

| Explanation artifact | Ridge | Single tree | Forest | Boosting | Linear leaf |
|---|---|---|---|---|---|
| Signed per-unit effect | Exact | No | No | No | Conditional on leaf |
| Path rule for one record | No | Exact and short | Long and non-unique | Very long | Long plus a linear expression |
| Global importance | Coefficient magnitude | Split usage | Gain or permutation | Gain or permutation | Gain plus coefficient magnitude |
| Counterfactual "what would change this score" | Solve one linear equation | Walk the path upward | Search over trees | Search over trees | Search plus invert the leaf fit |
| Stability of the above across retrains | High | Low | Medium | Medium | Medium to low |

The stability row is the one that breaks review conversations. A single tree's path rules can change completely after a retrain on one extra week of data, so a written explanation attached to a decision can be unreproducible a month later. A linear model's coefficient explanation is far more likely to survive, even if the model is slightly less accurate.

### 7.5 Sizing guide by row count and feature count

Values are ILLUSTRATIVE engineering estimates for a single machine, from the cost model in §9.

| n rows | d features | Recommended starting model | Expected fit time | Why |
|---|---|---|---|---|
| 500 | 10 | Ridge or depth-2 boosting with 100 rounds | Seconds | Below this size, variance in the estimate dominates family choice |
| 20,000 | 30 | Depth-3 boosting, 300 rounds, `nu = 0.05` | Under a minute | Enough rows for three-way interactions |
| 200,000 | 60 | Depth-6 boosting, 300 rounds, histogram bins | 1–10 minutes | Histogram binning pays off above roughly 50k rows |
| 2,000,000 | 200 | Depth-6 to 8 boosting with row and column subsampling | Minutes to an hour | Sorting per node becomes the bottleneck without binning |
| 20,000,000 | 500 | Distributed boosting or a linear model on engineered interactions | Hours | Single-machine memory binds before compute does |

### 7.6 The tie-break rules

When two candidates are within noise of each other, the tie-break is not "pick the higher number". Use these in order.

1. **Lower operational complexity.** Fewer moving parts, fewer artefacts, fewer version pins.
2. **Faster retrain.** A model that can be refit nightly is easier to keep honest than one that takes a week.
3. **Better explanation stability.** Prefer the model whose explanation survives a retrain.
4. **Fewer hyperparameters that matter.** A model whose score is insensitive to its settings is safer to hand over.
5. **Only then, the score.** A 0.002 AUC difference is not a reason to accept four extra failure modes.
