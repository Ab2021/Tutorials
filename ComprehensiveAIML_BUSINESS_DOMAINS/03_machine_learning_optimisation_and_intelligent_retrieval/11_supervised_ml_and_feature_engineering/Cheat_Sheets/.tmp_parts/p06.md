
## 6. Visual / Geometric Intuition

### 6.1 The linear boundary and the staircase

Picture a two-dimensional feature plane with a target that is 1 above the diagonal line `x2 = x1` and 0 below. A linear model draws one straight boundary and is perfect. A depth-1 tree can only cut parallel to an axis, so it is wrong in two triangular regions whose total area is a fixed fraction of the unit square regardless of where it cuts.

```text
GEOMETRY OF APPROXIMATING A DIAGONAL STEP                LTB-30
   depth-1 tree, one axis cut at t:   error area = t^2/2 + (1-t)^2/2
     t = 0.5  ->  0.125 + 0.125 = 0.2500
   depth-D tree with an even staircase of K = 2^D steps:
     each step of width 1/K contributes a triangular sliver of area (1/K)^2/2
     total = K * (1/K)^2 / 2 = 1/(2K)
   K = 16   (D = 4)  ->  1/32  = 0.031250
   K = 256  (D = 8)  ->  1/512 = 0.001953
   K = 4096 (D = 12) ->  1/8192 = 0.000122
```

Two things follow. First, the error falls as `1/K`, i.e. exponentially in depth — a factor of two per extra level of depth, not per extra tree. Second, reaching an error of `0.001` needs `K = 500` steps, which is depth 9, which needs up to `2^9 = 512` leaves and enough rows to populate them. A linear model reaches error zero with one boundary and two parameters. That asymmetry is the whole argument for checking linearity before reaching for depth.

### 6.2 The staircase is not free at the edges

The `1/(2K)` figure assumes the steps are placed optimally, which greedy splitting does not guarantee. Greedy CART places each cut where it reduces impurity most *at that node*, and for a diagonal target the locally best cut is often not the cut that a global staircase wants. The practical consequence: real trees need depth larger than the theoretical staircase bound, and the shortfall shows up as a wobbling, uneven staircase at the boundary rather than a smooth ramp.

The diagnostic is to plot the fitted function against the feature that should drive the diagonal. An uneven staircase with repeated cut values clustered in one region indicates greedy myopia, not insufficient depth. Adding depth then produces more steps in the crowded region only.

### 6.3 Axis cuts versus oblique cuts

```text
   linear boundary (1 cut)          depth-2 staircase (3 cuts)
   x2                               x2
   |      /                         |    +--+
   |    /                           |    |  |
   |  /                             | +--+  |
   |/                               ||  |  |
   +------------ x1                 +----------- x1
   exact for a diagonal step        error 1/(2*4) = 0.125 at best
```

Oblique cuts — combinations such as `x1 + x2` — would match the diagonal in one split, and some tree variants support them by augmenting the feature set with linear combinations. The cheap version of that idea is a linear leaf (§4.3 Variant C), which matches the trend *inside* each box rather than reorienting the boxes.

### 6.4 What a linear leaf does to the picture

A constant leaf draws a horizontal plateau over its box. A linear leaf draws a tilted plane over the box. If the target is a global ramp plus a local bump, the linear-leaf tree represents the ramp with one tilt per leaf instead of rebuilding it from dozens of axis cuts. The failure picture is equally clear: when a leaf holds three points, the tilted plane passes exactly through them and the resulting surface has a spike wherever the next leaf begins with a different tilt. Continuity across leaf boundaries is not enforced by the fit, which is why linear-leaf models can look worse than constant trees on small leaves even when their training error is lower.

### 6.5 The bias-variance U as a function of depth

```text
   validation loss
        |
        |\                          ridge / shallow tree underfit
        | \                         (bias dominated)
        |  \
        |   \___
        |       \___                minimum: depth 3-6 for tabular data
        |           \___
        |               \___        deep, unshrunk: variance dominated
        +----------------------- depth
          1   3   5   7   9   12
```

The curve is not symmetric. On the left the loss rises slowly as depth grows because each added level buys real structure. On the right it rises fast once depth exceeds the point where each leaf can hold enough rows to estimate a constant. The asymmetry is why "try depth 3 first, then go deeper only if the learning curve says so" beats "search depth from 1 to 20".

### 6.6 The learning curve tells you which knob

Plotting validation loss against training-set size separates the two failure directions more cleanly than any single number.

| Shape | Training loss | Validation loss | Gap closes with more data? | Knob to turn |
|---|---|---|---|---|
| Both high, gap small | 0.42 | 0.45 | Slowly | Add features or capacity |
| Train low, val high | 0.11 | 0.38 | Yes | More rows, then regularise |
| Train low, val high, flat curve | 0.08 | 0.36 | No | The validation set is not representative |
| Both low, gap small | 0.15 | 0.17 | — | Stop; the problem is solved at this loss |

The third row is the one that gets misdiagnosed. A gap that does not close as data grows is not a variance problem; it is a distribution problem, and no amount of `lambda` will close it. The discriminating check is to refit with data from the deployment period only, then see whether the gap survives.

### 6.7 The additive view of a fitted model

A boosted model with 300 trees of depth 6 is a sum of 300×63 = 18,900 leaf contributions. Visualising it as a surface is impossible, so practitioners visualise it as a sequence of partial-dependence curves and hope the sum is legible. The honest alternative is to plot the *first* few trees' contributions separately: the first tree usually captures the dominant effect and the later trees capture corrections that are individually small. If the later trees carry contributions of the same magnitude as the first, the model is not additive in any useful sense and the partial-dependence plots will mislead.

```text
magnitude check                                          LTB-31
   tree 1 leaf values:  range 2.4 log-odds
   trees 2-50 leaf values: median absolute 0.31 log-odds
   -> later trees carry 0.31/2.4 = 12.9% of the first tree's movement, so an
      additive reading is defensible
   if instead trees 2-50 had median absolute 2.2, the sum is an interaction
      soup and no single curve represents the model
```
