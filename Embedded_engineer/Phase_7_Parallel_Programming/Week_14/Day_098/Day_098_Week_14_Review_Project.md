## 📚 Prerequisites & Preparation

### Theoretical Background

*   **Strength Reduction:** A classic optimization where expensive operations (multiply/divide) are replaced by cheaper ones (shift/add).
*   **LLVM Pattern Matching:** Using `dyn_cast` and `match`ers to find optimization candidates.

### Project Scope

We will build a plugin `StrengthReduction.so` that:
1.  Iterates over all instructions.
2.  Looks for `mul` and `udiv`/`sdiv`.
3.  Checks if the second operand is a Power of Two Constant.
4.  Replaces the op with `shl` (shift left) for mul, or `lshr`/`ashr` (shift right) for div.

## 📖 Theoretical Deep Dive: Pattern Matching

LLVM provides a powerful template-based pattern matching library in `llvm/IR/PatternMatch.h`.

**Example:**
Instead of:
```cpp
if (auto *BinOp = dyn_cast<BinaryOperator>(I)) {
  if (BinOp->getOpcode() == Instruction::Add) {
    if (auto *C = dyn_cast<ConstantInt>(BinOp->getOperand(1))) { ... }
  }
}
```

Use Matchers:
```cpp
using namespace llvm::PatternMatch;
Value *X;
APInt C;
if (match(I, m_Add(m_Value(X), m_ConstantInt(C)))) {
    // X is the register, C is the actual integer value
}
```

## 💻 Implementation: The Strength Reduction Pass

### File: `StrengthReduce.cpp`

```cpp
#include "llvm/IR/PassManager.h"
#include "llvm/Passes/PassBuilder.h"
#include "llvm/Passes/PassPlugin.h"
#include "llvm/IR/PatternMatch.h"
#include "llvm/Support/raw_ostream.h"

using namespace llvm;
using namespace llvm::PatternMatch;

namespace {

struct StrengthReducePass : public PassInfoMixin<StrengthReducePass> {

  PreservedAnalyses run(Function &F, FunctionAnalysisManager &FAM) {
    bool Changed = false;
    
    // Iterate instructions. Note: Modifying the list while iterating requires care.
    // Standard pattern: collect "dead" instructions to remove later, or replace in place.
    
    for (auto &BB : F) {
      for (auto &I : BB) {
        
        // --- Case 1: Multiply by Power of 2 ---
        Value *X;
        APInt C; // Arbitrary Precision Integer
        
        // Match: X * C
        if (match(&I, m_Mul(m_Value(X), m_ConstantInt(C)))) {
          // Check if C is power of 2
          if (C.isPowerOf2()) {
             // log2(8) = 3. We shift left by 3.
             unsigned ShiftAmt = C.logBase2();
             
             // Create Shift Instruction
             // We need an IRBuilder or just manual creation
             IRBuilder<> Builder(&I); // Insert before I
             
             Value *Shifted = Builder.CreateShl(X, ConstantInt::get(I.getType(), ShiftAmt));
             
             // Replace all uses of 'I' (the Mul) with 'Shifted'
             I.replaceAllUsesWith(Shifted);
             
             // Mark 'I' for deletion (or let DCE handle it later, but good practice to kill)
             // We can't delete immediately inside loop iterator usually.
             Changed = true;
          }
        }
        
        // --- Case 2: Unsigned Divide by Power of 2 ---
        // Match: X / C (unsigned)
        if (match(&I, m_UDiv(m_Value(X), m_ConstantInt(C)))) {
             if (C.isPowerOf2()) {
                 unsigned ShiftAmt = C.logBase2();
                 IRBuilder<> Builder(&I);
                 // Logical Shift Right (zeros come in)
                 Value *Shifted = Builder.CreateLShr(X, ConstantInt::get(I.getType(), ShiftAmt));
                 I.replaceAllUsesWith(Shifted);
                 Changed = true;
             }
        }
      }
    }

    return Changed ? PreservedAnalyses::none() : PreservedAnalyses::all();
  }
};

} // namespace

extern "C" LLVM_ATTRIBUTE_WEAK ::llvm::PassPluginLibraryInfo
llvmGetPassPluginInfo() {
  return {LLVM_PLUGIN_API_VERSION, "StrengthReduce", "v0.1",
          [](PassBuilder &PB) {
            PB.registerPipelineParsingCallback(
                [](StringRef Name, FunctionPassManager &FPM,
                   ArrayRef<PassBuilder::PipelineElement>) {
                  if (Name == "strength-reduce") {
                    FPM.addPass(StrengthReducePass());
                    return true;
                  }
                  return false;
                });
          }};
}
```

### Build Script (`CMakeLists.txt`)

## 🧪 Verification & Testing

### Test Case 1: `mul_test.ll`

```llvm
define i32 @test_mul(i32 %a) {
  %res = mul i32 %a, 8
  ret i32 %res
}
```

### Running the Pass

```bash
# 1. Build plugin
cd build && make

# 2. Run opt
opt -load-pass-plugin ./StrengthReduce.so -passes="strength-reduce" -S ../mul_test.ll -o output.ll
```

### Expected Output (`output.ll`)

```llvm
define i32 @test_mul(i32 %a) {
  %1 = shl i32 %a, 3
  ret i32 %1
}
```
*Success! `mul` became `shl` with constant 3 (since $2^3 = 8$).*

### Corner Cases (Self-Correction/Critique)
1.  **What about `mul i32 8, %a`?**
    *   `m_Mul` matches commutatively? No, usually `instcombine` canonicalizes constants to the right side (`mul %a, 8`). If we run on unoptimized code, our matcher `m_Mul(m_Value(X), m_ConstantInt(C))` expects constant on RHS.
    *   Robust fix: Match `m_Mul(m_Value(X), m_ConstantInt(C))` OR `m_Mul(m_ConstantInt(C), m_Value(X))`.
2.  **What about Signed Division (`sdiv`)?**
    *   `sdiv x, 2` is NOT `ashr x, 1` for negative numbers!
    *   `-3 / 2 = -1` (in C99).
    *   `-3 >> 1 = -2` (arithmetic shift usually rounds towards $-\infty$).
    *   **Fix:** Strength reduction for signed division requires fixups (adding a bias). We omitted `sdiv` for simplicity, but a real compiler handles this.
