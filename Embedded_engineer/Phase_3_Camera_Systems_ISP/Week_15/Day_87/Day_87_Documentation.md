## 📖 Theoretical Deep Dive

### 🔹 Part 1: The Datasheet
*   The "Face" of the product.
*   **Sections:**
    1.  **Features:** Bullet points (4K, HDR, IP69K).
    2.  **Key Specifications:** Table (Res, FPS, SNR, Power).
    3.  **Pin Configuration:** Pin 1 = VDD, Pin 2 = GND...
    4.  **Mechanical Drawing:** Dimensions, Screw holes.
    5.  **Optical Characteristics:** FOV, Distortion, MTF.

### 🔹 Part 2: API Documentation
*   If the camera has a REST API or SDK, it needs docs.
*   **OpenAPI (Swagger):** The standard for REST APIs.
*   **Example:** `GET /api/v1/stream/start`.

### 🔹 Part 3: User Manual
*   **Audience:** The Technician installing the camera.
*   **Content:**
    *   **Safety:** "Disconnect battery before installing."
    *   **Mounting:** "Torque screws to 2.5 Nm."
    *   **Cleaning:** "Use microfiber only. No alcohol."

### Example 2: Doxygen Configuration (`Doxyfile`)

Auto-generating HTML docs from C++ comments.

```ini
PROJECT_NAME           = "TrafficCam Firmware"
OUTPUT_DIRECTORY       = docs
INPUT                  = src include
RECURSIVE              = YES
GENERATE_HTML          = YES
GENERATE_LATEX         = NO
EXTRACT_ALL            = YES
```

**Code Commenting Style:**

```cpp
/**
 * @brief Initializes the Camera Sensor.
 * 
 * Sends the startup sequence via I2C.
 * 
 * @param i2c_bus The I2C bus number (0-2).
 * @return int 0 on success, -1 on failure.
 */
int camera_init(int i2c_bus);
```

## 🐛 Debugging Documentation Issues

### Debug 1: "It doesn't work like the manual says"

**Symptom:** User follows steps, but fails.

**Cause:**
*   Firmware changed, manual didn't update (Drift).
*   **Fix:** Version control your documentation *with* the code. (Docs as Code).

### Debug 2: Ambiguous Specs

**Symptom:** Customer complains "Low Light is bad", but Datasheet says "High Sensitivity".

**Cause:**
*   Vague terms.
*   **Fix:** Use numbers. "Sensitivity: 2000 mV/µm²" or "SNR: 30dB @ 1 Lux".

## ⚡ Performance Optimization

### Optimization 1: Searchable Docs

*   Use tools like **MkDocs** or **Sphinx** (for Python) which generate a static site with a Search Bar.
*   Nobody reads PDFs linearly. They search for "Reset".

### Optimization 2: Interactive API Docs

*   Host Swagger UI on the camera itself (`http://camera-ip/docs`).
*   Allows developers to test the API directly from the browser.

## 📝 Assessment Questions

### Conceptual Questions

1.  **Why is "Version Control" important for docs?** (To match the doc version with the software version).
2.  **What is the purpose of a "Pinout Diagram"?** (To prevent the user from frying the board by connecting 12V to GND).
3.  **Difference between "User Manual" and "Service Manual"?** (User = Operation. Service = Repair/Schematics).
4.  **What is "Errata"?** (A document listing known bugs/mistakes in the datasheet).

### Practical Challenges

1.  **Draft a Release Note:** "Firmware v1.2.0. Fixed: Pink corners. Added: MQTT support. Known Issue: WiFi slow on startup."
2.  **Draw a Block Diagram:** Use Mermaid.js or Draw.io to show the internal blocks (Sensor, ISP, CPU, PMIC) for the datasheet.
