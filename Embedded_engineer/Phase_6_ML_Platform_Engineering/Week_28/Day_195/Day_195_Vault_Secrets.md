## 📖 Theoretical Foundation

### 1. The Secret Sprawl
*   **Env Vars:** Leaks in logs (`ps aux`).
*   **K8s Secrets:** Just Base64 encoded. Anyone with `kubectl get secrets` can read them. No rotation.
*   **Vault:**
    *   **Encrypted:** At rest and in transit.
    *   **Dynamic:** "Give me an AWS Key". Vault creates one valid for 1 hour.
    *   **Revocable:** "Revoke all keys for User A".

### 2. Architecture
*   **Storage Backend:** Where encrypted data lives (Consul, Raft, S3).
*   **Barrier:** The "Door". Sealed on startup. Needs Unseal Keys (Shamir's Secret Sharing) to open.
*   **Auth Methods:** Kubernetes Auth (Pod JWT), GitHub Auth, LDAP.

## 💻 Implementation

### 👨‍💻 Infrastructure: Install Vault

```bash
helm repo add hashicorp https://helm.releases.hashicorp.com
helm install vault hashicorp/vault \
    --set "server.dev.enabled=true" # Dev mode (Auto-unsealed) for learning
    --set "injector.enabled=true"
```

### 👨‍💻 Infrastructure: Secret Injection (Agent Sidecar)

The modern way. No code changes needed.

#### 📁 `manifests/pod-with-secret.yaml`
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app
  annotations:
    # 1. Enable Agent
    vault.hashicorp.com/agent-inject: "true"
    # 2. Define Role
    vault.hashicorp.com/role: "app-role"
    # 3. Define Secret Path
    vault.hashicorp.com/agent-inject-secret-config: "secret/data/my-app"
    # 4. Define Template (Format output)
    vault.hashicorp.com/agent-inject-template-config: |
      {{ with secret "secret/data/my-app" -}}
      export DB_PASS="{{ .Data.data.password }}"
      {{- end }}
spec:
  serviceAccountName: app-sa
  containers:
  - name: app
    image: alpine
    command: ["sh", "-c"]
    args:
    - "source /vault/secrets/config && echo DB_PASS is $DB_PASS && sleep 1h"
```

### 👨‍💻 Core Implementation: Dynamic AWS Credentials

Never hardcode `AWS_ACCESS_KEY_ID` again.

```bash
# 1. Enable AWS Engine
vault secrets enable aws

# 2. Configure Root Creds (Vault uses these to create children)
vault write aws/config/root \
    access_key=... \
    secret_key=... \
    region=us-east-1

# 3. Create Role (Policy)
vault write aws/roles/s3-readonly \
    credential_type=iam_user \
    policy_document='{
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": "s3:GetObject",
          "Resource": "*"
        }
      ]
    }'

# 4. Request Creds (Client Side)
vault read aws/creds/s3-readonly
# Output:
# access_key: AKIA... (New)
# secret_key: ...
# lease_duration: 1h
```

## 🔬 Lab Exercise: "The Leaked Key"

### Task
Simulate Breach Response.
1.  **Scenario:** Developer accidentally pushes `AWS_ACCESS_KEY_ID` to GitHub.
2.  **Detection:** Security Team notices.
3.  **Old Way:** Panic. Log in to AWS Console. Find user. Rotate key. Update 50 apps. Restart 50 apps. (Downtime).
4.  **Vault Way:**
    *   Command: `vault lease revoke -prefix aws/creds/s3-readonly`.
    *   Result: All keys generated by that role are immediately invalid.
    *   Apps: Apps request a *new* key automatically via Sidecar/Agent. Zero Downtime.

## 📖 Advanced Theory: Shamir's Secret Sharing
When Vault starts in Prod, it is **Sealed**. It cannot decrypt data.
*   **Unsealing:** Requires 3 out of 5 Keys.
*   **Process:**
    *   Admin A runs: `vault operator unseal <Key1>` (Progress: 1/3)
    *   Admin B runs: `vault operator unseal <Key2>` (Progress: 2/3)
    *   Admin C runs: `vault operator unseal <Key3>` (Progress: 3/3 -> Unsealed).
*   **Security:** No single admin can steal the data.

## 📝 Daily Summary

### Key Takeaways
1.  **Kubernetes Auth:** Vault trusts K8s. When a Pod starts, it sends its `ServiceAccount` JWT to Vault. Vault verifies the signature with K8s API. If valid, Vault issues a Vault Token to the Pod.
2.  **Rotation:** Static secrets (passwords) are dangerous because people forget to rotate them. Dynamic secrets rotate automatically (TTL).
3.  **External Secrets Operator (ESO):** Alternative to Vault Sidecar. ESO syncs Vault Secrets -> Kubernetes Secrets. Easier for legacy apps, but less secure (secrets exist in Etcd).
